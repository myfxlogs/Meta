## 0. 一句话

一套无人值守的多 agent 协作开发公司：业主只和 CEO 说话，其余全是事件驱动的无头席位，由一个无智能的 **网关（Gateway）** 编排；任一壳失效自动换壳；全链 gRPC 流；零轮询、零心跳、零 JSON。

## 1. 红线（不可协商，接手者不得「优化」掉）

| # | 红线 | 为什么 |
|---|---|---|
| R1 | **全无人**：需求→生产零人工闸；业主只在 CEO 对话面出现 | 目的本身 |
| R2 | **禁周期任务 / 禁轮询 / 禁心跳 / 禁快照表**。唯一允许的时钟=「随事件重置的一次性闹钟」 | v1 死于心跳假活与扫表幻影 |
| R3 | **meta 内部契约零 JSON**（接口/存储/事件全 protobuf）。外部工具的 JSON 止于适配层 | 手写 JSON 出错率高于 proto |
| R4 | **全链 gRPC 流，含浏览器**（Connect 二进制模式） | 一种传输，一种契约 |
| R5 | **票只活在 DB**；仓库不承载任务状态 | v1 死于文件相位 vs DB 相位双源 |

借鉴开源**只借设计与架构，不借实现**（Paperclip/OpenClaw/Grok Ship 等全为心跳+JSON+REST，见 `技术选型.md`）。

**R2 边界条款**：R2 约束的是**业务发现机制**——禁用时间维度去发现死亡/状态/进度。传输层与第三方库内部的保活/重试（gRPC HTTP/2 keepalive、飞书 WS 长连接 SDK 心跳、SQLite checkpoint、壳 CLI 内部重试）不受此限。一方代码中的**有界重试链**（退避 N 次后放弃）＝一次性闹钟链，合法；无限周期巡检，违法。

## 3. 网关（唯一的非智能体进程）

**是**：席位进程的父进程、票状态的唯一写者、事件的唯一出口、壳路由器、闸执行者、飞书通道持有者。

**不是**：不做任何判断。它出事件、执闸、换壳；一切需要「想」的事交给智能体（CTO/审计/CEO）。

### 3.1 四面接口（全 gRPC）

| 面 | 传输 | 内容 |
|---|---|---|
| 席位面 | 本机 Unix domain socket，双向流 | 领票 / 进度帧 / 交付 / 许可问答 / 用量上报 |
| CEO 面 | 本机 socket | 事件流订阅；需求提交；裁决提交；记忆读写 |
| 前端面 | Connect，**二进制 protobuf** | `SeatBoard` 服务端流 |
| 外部面 | 飞书 **WS 长连接**（官方 SDK `larkws`，vend 推送）+ HTTP 入站 webhook | 凭证经 `secret` 表+`Secret(name)` RPC（ACL 按角色，见 `docs/凭证清单.md`）；**自动需求经此入（§6.3）**；JSON 止于适配层 |

### 3.2 存储：SQLite（WAL）

- 单写者进程 ↔ 嵌入式单写者库；无 NOTIFY、无权限表、无跨机
- proto 二进制存 BLOB；需查询的字段另立索引列
- 表：`ticket` / `ticket_event` / `seat` / `seat_run` / `shell` / `project` / `ceo_memory` / `budget` / `secret`（AES-256-GCM 密文，主密钥=`run/vault.key` 0600；凭证全进库，见 `docs/凭证清单.md`）
- `seat_run`＝每实例一 run：run_id / 票 / 角色 / 壳 / 退出码 / 输出日志文件路径——CTO 裁决读「输出流尾部」与事后取证皆从此出；日志每 run 一文件，按配额保留
- 备份＝`VACUUM INTO`（或 backup API）——WAL 热库上直接拷文件会丢最近提交/撕裂；触发＝每 N 票完成事件＋业主 CLI，非定时

### 3.3 唯一写者原则

任何状态变更都是对网关的 gRPC 调用；**事件就是调用本身**，不存在「写了没人发现」。DB 是持久日志不是总线。网关重启=一次**启动对账**（见 §5.3），不是周期扫描。

### 3.4 安全最小集

席位跑的是半任意 LLM 生成码——安全必须是机械闸，不能只是提示词禁线：

- **run token**：网关 spawn 每实例注入一次性令牌；席位面/CEO 面流**首帧必验**（见 §12），验不过＝断流
- **socket 权限**：socket 目录 0700；前端面绑 loopback＋接入 token
- **降权与只读**：席位以独立低权用户运行；部署树对席位只读 bind；远端仓开保护支——细则归项目配方**「沙箱形制」**栏（§11）
- **CEO 破坏性裁决**（作废/杀）须重述确认帧——防注入链（仓内容→施工自述→判决史→CEO 上下文→`Rule`）
- 高危凭证（`dsn.fin`）收敛：只读账号或网关代跑——**待业主单独裁，裁前不入 ACL**

## 4. 席位与角色卡

| 席 | 形态 | 职责 | 禁线 | 壳 |
|---|---|---|---|---|
| CEO | 唯一交互席（+事件触发的无头分身） | 业主的**全权代理人**：业务决策自裁＋事后告知；对 CTO 指导定向；出需求；系统告知转达 | 不设计/不写码/不审；不定 CTO 方案细节（定向除外） | **业主指定** |
| CTO | 无头，事件触发，无状态 | 需求→设计文档→拆票→派发；审计通过→部署 | 不写实现码；不审 | 系统选 |
| 审计 | 无头，**独立实例** | 对票面+设计验收交付；出判决 | 不改码；不设计 | 系统选，优先与该票 CTO **异壳** |
| 施工 | 无头，事件触发 | 领票→实现→自测→提交→交付 | 不超票/不自审/不部署/不碰部署树 | 系统选 |

**角色卡**（`roles/<席>.md`）：每席一页机械契约——身份、必读、必产、禁线、进度帧义务、卡住怎么办。网关 spawn 任一实例时**注入角色卡+票面+项目配方**为提示前缀。**壳可换，角色不漂。** 角色卡随仓库版本化，改动走票。

实例规则：一实例一角色全程不换；记忆在 DB 与项目仓文档，不在进程；每票一施工实例、每需求一 CTO 实例、每验收一审计实例；并行上限由预算配置。

**经验库**〔令#E1·业主令 2026-11-01〕：`docs/经验库/` 一坑一文，**遇到就写，不等统一归纳**——任何席位（含手工径）在坑被解决的当下即写即 commit。它是「记忆在项目仓文档」的落点：实例死，经验不死。网关注入角色卡时附带其索引（阶段 2 起机械实现）。

## 5. 席位生命周期与死亡检测

### 5.1 先连后领（结构消灭「派了没起」）

```
网关 spawn 进程（父子；独立 systemd scope）
 → 进程连网关 socket（双向流）
 → 进程发 Claim(ticket)
 → 网关写 施工中
```

无连接即无「施工中」。spawn 失败是同步返回值→立即换壳重起。

**连接方向钦定**：正常径＝席位 Attach 网关主 socket；网关 spawn 时另分配 per-seat UDS（`run/seats/<run_id>.sock`），席位**同时监听之，仅供重启收养**（消除「席位连网关」vs「网关连席位」的方向矛盾）。席位侧流断（网关死）＝装一次性闹钟（缺省 10min）：闹钟内被收养＝续跑；闹钟到＝自行退出。席位禁无限自行重连。

**收养互证**：收养连接的**首帧＝网关出示 run_token**（它发的它知道），席位验不过＝拒绝续跑并退出；per-seat socket 文件 0600、属主＝席位用户——防本地进程冒充网关喂假票/截交付。

### 5.2 四死法 × 事件源（零心跳）

| 死法 | 事件源 | 时钟 |
|---|---|---|
| 派了没起 | 结构消灭 + spawn 同步返回 | 无 |
| 中途死 | 父进程 `SIGCHLD` + socket EOF 双源互证（本机 socket 无需 keepalive） | 无 |
| 活着但卡死 | **进度帧闹钟**（一次性，随每帧重置，缺省 30min）+ **token 预算**耗尽 → 事件给 CTO 裁：杀+回队换壳 / 延期；**延期计数入票，K 次（缺省 2）后只余 杀+回队 或 报 CEO** | 兜底唯一一处 |
| 网关死 | 席位在独立 scope 不随死；网关重启做**一次启动对账** | 无 |

### 5.3 启动对账（全相位）

网关启动时，对**每个非终态票**按「相位×预期行动者」核对——只在启动事件发生，不周期：

| 相位 | 预期行动者 | 活着 | 死/无 |
|---|---|---|---|
| 施工中 | 施工实例 | 收养（经 per-seat socket） | 回队 `已派` |
| 设计中 | CTO-A 实例 | 收养 | 回 `已立` 重派 |
| 审计中 | 审计实例 | 收养 | 回 `待审` 重起审计（**不计驳回**） |
| 部署中 | CTO-B 实例 | 收养 | 回 `待部署` 重起（先核回滚态） |
| 已派/待审/待部署 | 无（等 spawn） | — | 补发下一步 spawn 事件 |

**闹钟重算**：`last_progress_at` 取自 `ticket_event`——已过期＝立即发「疑似卡死」；未过期＝闹钟设到原 deadline。否则网关崩溃循环会永久饿死卡死检测。

### 5.4 进度帧

席位义务：阶段切换即推一帧 `Progress{stage, note}`，stage ∈ {调查, 设计, 写码, 自测, 提交, 交付}。它同时是：① 健康判据（距上帧时长） ② 前端席位板的「正在做什么」。

### 5.5 预算

每票 token 上限（角色缺省，CTO 票面可覆盖）。壳适配器从壳输出流读用量，累计上报网关；达阈=事件：席位须交付或让位。80% 警告事件→CEO；100% 硬停。

**口径钦定**：80/100% 是**每次尝试内**的闸；另有**票级累计硬顶**——跨尝试、跨壳、跨驳回求和（CTO/审计/重做各实例对本票的消耗**计入**同一硬顶）。达顶＝票标 `budget_frozen`（阻后续 spawn，相位不动）＋事件→CEO；CEO 裁「作废」或「追加预算复活」——硬顶止血而不越「作废＝CEO 令」的权（合议改：原拟机械作废）。防一张病票在壳间循环、每轮重领满额预算，无人拦地烧钱。

**冻结细则**：硬顶到达时若席位仍活＝先按 100% 硬停杀本尝试，**再**置 `budget_frozen`；冻结同时取消该票全部未决闹钟与排队事件（冻票无活性，不留幽灵事件）。CEO「追加预算复活」＝**抬帽不清零**——累计计数单调递增，防循环复位再烧。

### 5.6 许可提示

壳全部无交互模式。壳流出现「请求许可」帧→网关自动答**拒**。席位不得挂着等人。

## 6. 票

### 6.1 契约八栏（缺一不派）

目标 / 为什么 / 范围内 / 范围外（禁线） / 设计引用（项目仓路径+commit） / 验收锚（机器可判清单） / 验证命令 / 交付形制（支名·提交格式·交付=推支+`Deliver`）。
附：预算、优先级、依赖票、**判决史**（驳回理由累积，重做者必读）。

### 6.2 相位与边

```
已立 → 设计中 → 已派 → 施工中 → 待审 → 审计中 → 待部署 → 部署中 → 完成
                 ↑         │                 │
                 └─ 回队 ──┘ 席死/卡死/换壳   │
                 ↑                           │
                 └──── 驳回（同壳重做）───────┘
任一非终态 → 作废（CEO 令）
```

- 边表钦定；越边=拒
- 驳回 N 次（缺省 3）→ 事件→CEO
- 回队保留判决史与施工痕（支不删）

补边（原图缺，钦定补全）：
- `设计中 →(CTO 席死)→ 已立`——重派
- `部署中 →(失败+已回滚)→ 待部署`——CEO 裁重试或作废；无此边则失败票永卡 `部署中`
- `审计中 →(审计席死)→ 待审`——重起审计，**不计驳回次数**
- `施工中 →(Yield)→ 已派`——Yield 理由入判决史，并触发 CTO 裁决（③级机器失效 or 票面病）

### 6.3 自动票：全自动项目的发起径

**问题**：发起者只有 CEO，而 CEO 的激活要么靠人（终端/飞书）、要么靠需判断的系统事件——全自动项目（哨兵成票、事件自愈）缺发起环；若让无头 CEO 兼任自动发起者，又与「同时刻最多一个 CEO 实例」冲突。

**解法＝自动环不放 CEO**：
- **发起径**：外部面事件（探针/哨兵/项目自身）→ 网关四道**机械闸**：①验签 ②去重键（同键在途票上限，缺省 1——防一个异常刷出 N 票）③自动票预算帽（缺省低于人工票）④项目配方「允许自动票」开关 → 过闸＝起 CTO（A 唤起，触发源＝外部事件），定性拆票照旧
- **第五道闸＝同键累计帽**：去重只数「在途」，挡不住「完成→再红→再票」的无限循环——闸时按 DB 计**同键历史票数（含已完成）**，超帽（缺省 3）＝不再自动成票，升级 CEO「疑系统性」（DB 计数随事件判定，无定时器，不违 R2）
- **需业务裁决才进 CEO 环**：CTO 判「需求待裁」（动钱/范围外/歧义）→ 事件→CEO，与既有径合流
- **CEO 锁语义**（§8）：锁＝互斥＋排队，不是独占阻塞——需判断事件到来时，有活跃 CEO 连接＝派发之；无＝起无头实例；切换期间事件**排队不丢**
- **事后告知，非事前审批**（§8.1 增）：自动票已立 / 自动票完成部署——业主保持「先于任何渠道知道」，但不阻塞自动链

## 7. 壳路由

**登记表**：壳 × 模型 × 适用角色 × 优先序 × 健康态。CEO 行业主写死；其余按序。

缺省序：CTO/审计 → devin swe-2-max > claude(GLM) > opencode；施工 → devin swe-2 medium/high > claude(GLM) > opencode。

| 级 | 现象 | 处置 | 报 CEO |
|---|---|---|---|
| ① | 起不来/秒退 | 换下一壳 | 是 |
| ②a | 限流/瞬态 API 错 | provider 并发闸＋错峰 spawn；恢复靠**懒探**（下次需要时试一次） | 否（恢复时报） |
| ②b | 配额尽/授权过期/持续 API 错 | 标不可用；换壳；懒探 | 是 |
| ③ | 无进度/预算尽 | 事件→CTO 裁 | 若换壳 |
| ④ | 审计驳回 | **不换壳**，同壳重做 | 否 |

**②级拆两态**：限流≠配额死——并行多席打同一 provider 的限流若与配额死同桶，会连锁标死全壳、误报「全壳耗尽」。

**适配器契约**：壳必须**前台 exec、禁 daemonize**——否则 SIGCHLD 对中间进程早到而真进程仍活、socket 不 EOF，双源互证被击穿。某壳做不到＝触发禁区「适配器做不出来」上裁。

**④同壳语义**：同壳＝**模型一致性偏好**，非会话续用——席位一律从票面＋判决史冷启动，壳自带 resume 不用（与「记忆不在进程」一致）。

**换壳=票级重做**（壳间会话不互通）。**CEO 是唯一人机出口**：需人工的（授权/配额/全壳死/模型调整）系统只做一件事——告诉 CEO。

## 8. CEO

- **记忆在 meta 库**（`ceo_memory`：备忘+决策记录）；任何 CEO 实例起来先读。不依赖壳自带记忆
- 交互实例：业主在终端时
- 无头实例（事件触发，不常驻）：飞书来话而无终端会话；需判断的系统事件（壳死/三驳/全壳耗尽）
- 纯机械通知（已部署/已换壳/壳恢复）网关直推飞书，不动模型
- **同一时刻最多一个 CEO 实例**——锁＝**活跃连接登记**（Attach 登记、EOF 除名），随启动对账自然重建，非内存布尔
- **事件派发规则**：需 CEO 的事件→有活跃连接＝派发之；无＝起无头实例；两态切换期间事件**排队不丢**。锁是互斥＋排队，不是阻塞——交互实例在场不会死锁自动环，只会让其裁决排队
- **最后呼救径**：CEO spawn 连败（其壳行全标死）→ 网关把排队事件**原文直推飞书**（机械模板，标注「CEO 不可起·需人工」）——网关活着而 CEO 壳全死时，系统仍有声音；这是 B4（网关崩溃径）之外的另一半
- **CEO 不在自动发起环**：全自动径见 §6.3，直达 CTO；CEO 只接业务裁决与告知
- **飞书通道归网关**（借 OpenClaw Gateway 形）：壳换通道不断；飞书入站=事件→起 CEO 实例
- 飞书接入=**官方 SDK WS 长连接**（事件推送，非 webhook 非轮询；vend 协议不受 R4 约束——R4 管 meta 内部链路）；凭证在 `secret` 表（迁移源与参考实现在 `docs/凭证清单.md`）

**权责——CEO 全权重构（反转）**：CEO 不再是「业务裁决转达口」，而是**业主的全权代理人**：

- **授权范围**：目标取舍、优先级、范围与放行/作废/重启、驳回处置、预算内追加、策略启用——业务性决定全权，自裁＋事后告知，不请示
- **业主指示优先**：业主在场的直接指示＞CEO 自主决策；冲突以业主**最新**指示为准——代理人不可据记忆推翻委托人
- **来源标记**：网关对每个进 CEO 的载荷机械打 provenance（`terminal` / `feishu:<白名单id>` / `system_event` / `auto`）——「业主指示」只认带 `terminal`/`feishu` 标的载荷；决策记录必须引用 provenance。防被注入的 CEO 虚构「业主最新指示」给裁决背书（机械可机检）
- **对 CTO 指导定向**：需求可附定向（方向/优先序/约束/边界）；CTO 在定向内自主技术设计；CEO 可重定向（退回重拆），但**不定方案细节**
- **质询权**：裁技术相关事项（三驳/病票/重定向）前，可 `Inquire(票/事件 ref＋问题)` 起一次 CTO 诊断实例——**只产诊断报告入 DB，不产票不派工**（全权不等于全知，问一句再裁）
- **裁量原则**：`ceo_memory` 有据依据；无据取**可逆性最大、成本最小**的选项，告知中标注「自主裁量」
- **问责对价**：每项自主决策入 `ceo_memory`（决策＋理由＋触发事件）——业主的控制从**事前审批**改为**事后复盘**，完整审计链是全权的代价；无头实例的决策同样留痕
- **仍归业主的**：要业主本人执行的动作（充值/登录授权/模型账号调整）——CEO 只能明说要业主做什么

### 8.1 必报 CEO 事件（可增不可减）

壳标不可用/恢复 · 任一票换壳 · 全壳耗尽 · 授权/配额/模型需人工 · 票完成部署 · 驳回达 N · 生产探针红→已回滚 · 预算 80% · **自动票已立/完成部署**

**哨兵边界**：「生产探针红」指**部署时刻**的探针。票 `完成` 后的持续监控属**外部系统**——其告警经外部面入站（§6.3 自动径）；meta 不自建周期监控。哨兵由此有了钦定的入水口。

**报 CEO ≠ 请示业主**：上列事件多数由 CEO **自裁＋告知**（驳回处置/重定向/作废/重启/降级）；仍需业主本人的只剩「授权/配额/模型」类——要业主掏钱或登录的动作。告知格式＝已裁＋为何。

## 9. 前端：席位板流

- 浏览器经 Connect（二进制）订阅 `SeatBoard`
- 接入即发一帧全席现态（角色/壳/模型/所领票/当前 stage/预算用量）；此后只推变化帧
- **不存历史、不做分页、不查过去**——业主只看现在
- 历史与取证的出口＝`meta` CLI 只读导出（票/事件/判决史）——「过去归 DB 审计面」的落点

## 10. 部署闸（全无人故全机械）

审计通过 → CTO 实例部署 → 三锚全绿=完成：① 审计判决=通过 ② 项目配方检查命令绿 ③ 部署后健康探针绿。任一红→自动回滚→事件→CEO。

- **命令代跑**：检查命令/验证命令由**网关代跑**，退码＋输出原文入 DB；diff 范围核对（范围内/外文件清单比对）＝网关机械前置闸。审计实例读机器记录做语义判断——**锚的绿由机器说了算，不由实例口述**（防测试造假骗锚、防审计放水；跑命令不是「想」，不违禁区#7）。**执行身份**：代跑**绝不得以网关自身用户 exec**——在项目配方「沙箱形制」指定的降权用户下跑，cwd＝网关预检出的交付 commit 干净 worktree，超时＝一次性闹钟，输出与退码挂 `seat_run`。网关用户持有 `vault.key`，同用户执行不可信码＝把全部凭证送人
- **项目级串行**：同项目 设计/集成/部署 三把队列锁（网关机械闸，事件驱动出队）；集成（merge 支）归 CTO-B，冲突＝事件→回 CTO 重拆票

## 11. 项目配方

meta 与项目无关。每项目登记：仓库地址 / 默认支 / 检查命令 / 部署命令 / 健康探针 / 回滚命令 / 项目自有纪律文档路径（注入席位提示）/ 预算 / **沙箱形制**（席位运行用户、部署树只读 bind、远端保护支）/ **自动票开关＋自动票预算缺省＋去重键规则**。

另登记两旗：**`auto_deploy_requires_ceo`**（自动票部署前须 CEO 放行——O 类钱径项目缺省开，meta 自身缺省关）；**重述确认类清单**（须重述确认帧的裁决类，缺省＝作废/杀，配方可扩：部署/删数据/对外发布）。
O 是第一个登记项目；O 仓规矩（AGENTS.md/check_all/worktree/经验库）是 **O 的配方**，不是 meta 的纪律。**先把 meta 自己跑通，再登记 O。**

## 12. 接口草图（名字定死，字段可在实现中补）

```
service SeatGateway {           // 席位面，unix socket
  rpc Attach(stream SeatMsg) returns (stream GatewayMsg);
}
SeatMsg   = Claim | Progress | Usage | Deliver | PermissionReply | Yield
GatewayMsg= Ticket | PermissionAsk | Abort | Extend

service CeoGateway {            // CEO 面
  rpc Events(Subscribe) returns (stream Event);
  rpc SubmitRequirement(Requirement) returns (TicketRef);
  rpc Rule(Ruling) returns (Ack);              // 延期/杀/作废/放行
  rpc Inquire(Inquiry) returns (Ack);          // 质询→起 CTO 诊断实例（只产报告不产票）
  rpc Memory(stream MemoryOp) returns (stream MemoryOp);
}

service Board {                 // 前端面，Connect 二进制
  rpc SeatBoard(Empty) returns (stream BoardFrame);
}
```

席位面/CEO 面流**首帧＝`RunAuth(run_token)`**（网关 spawn 注入，验不过＝断流）；`Secret(name)` 归席位面消息集。自动需求＝网关从外部面事件内部生成 `Requirement` 起 CTO，不经 `SubmitRequirement`（该 RPC 仍是 CEO 专属）。Event 载荷一律带 **provenance 字段**（来源标，见 §8）。

## 13. 自举计划（阶段锚全机器可判）

| 阶段 | 交付 | 验收锚 |
|---|---|---|
| 0 | 网关骨架：SQLite+`SeatGateway.Attach`+票相位边表+启动对账 | 单测：先连后领；越边拒；杀进程→SIGCHLD+EOF 双源回队；重启收养/回队 |
| 1 | 壳适配器 ×3 + 壳路由 + 预算 + 进度闹钟 | 三壳各起一真会话成功；杀 devin 进程→自动换 claude 重做；30min 无帧→事件 |
| 2 | 角色卡注入 + CTO/审计/施工三席跑通一张真票（票=meta 自己的下一个功能） | **meta 用自己派自己的票并通过审计**=自举完成 |
| 3 | CEO 面 + 飞书通道 + 前端席位板 | 飞书发一句需求→前端看到施工中→飞书收到「已部署」 |
| 4 | 登记 O 项目配方 | O 的一张真票全链走完 |

阶段 0–1 由业主当前会话以临时 CTO+审计身份手工起施工席（v1 归档里的 `devin -p` 径），阶段 2 起 meta 自派。

**阶段锚修订**：
- 阶段 0 验收锚升级为**全相位对账**（非仅 `施工中`）：于各相位杀网关→重启后按 §5.3 表逐相收养/回队/补 spawn；闹钟按 DB 重算
- **阶段 2 前置二件**：① 命令代跑（§10）——meta 自审的可信度全靠它；② **自升级回滚**——systemd `OnFailure`＋`StartLimitBurst` 崩溃循环自动回退上一版二进制（保留 N 版），OnFailure 脚本直推飞书**不经模型**；meta 升级票的第三锚＝「重启后全相位对账绿」
- 阶段 4 增收**自动票径**：模拟哨兵事件→验签过闸→自动成票→全链→飞书收「自动票已立/已部署」事后告知
- 阶段 0 增收**安全锚**：伪连接（无 token/错 token）被断流；收养首帧出示 run_token、席位验拒留痕——A7/D2 最小集进锚，安全不留到阶段 2 补

**实现区钦定（`docs/实现/`）**〔令#E2·业主令 2026-11-01〕：自举期（网关未立）一切「本应进 DB 的东西」的真源暂存处。固化目的：**会话里长出来的状态、决定、票面，不许只活在会话里**——壳换了、实例死了，档案还在。

| 文件 | 是什么 | 何时写 | 归宿 |
|---|---|---|---|
| `ceo_memory.md` | CEO 决策迁移源（决策＋理由＋触发＋provenance） | 每个 CEO 实例**接手第一件事＝读**；每次决策即写 | 网关立起一次性导入 `ceo_memory` 表后归档 |
| `票-*.md` | 手工径票面草稿（八栏齐） | 阶段 0–1 派票时（业主会话戴临时 CTO 帽） | 票入 DB 后归档不再更新（R5 例外仅限自举期） |

判据一句话：有网关走 gRPC 进 DB；没网关落本区；坑一律进 `docs/经验库/`（令#E1，与是否自举无关）。任何席位接手＝先查本区有无未归档档案。
