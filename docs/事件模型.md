## 总原则

1. **编排器是任务状态的唯一写者。** 席位、CEO、外部源（webhook）全部通过 gRPC 调编排器改状态；没有第二条写径，也就没有「写了没人发现」的事件丢失——**事件就是调用本身**。DB 是持久日志，不是总线。
2. **发现死亡看连接，不看时间戳。** 没有心跳这个东西。
3. **唯一允许的时钟**：随事件重置的一次性闹钟（没有事件时才响，有事件即推后）。禁止任何周期扫描。
4. 编排器自身不含智能；它出事件，智能体（CTO/审计/CEO）做裁决。

## 席位生命周期（结构消灭「派了没起」）

```
编排器 spawn 席位进程（父子关系，独立 systemd scope）
  → 席位连上编排器（本机 Unix domain socket，双向 gRPC 流）
  → 席位经流发「领票」
  → 编排器写 施工中
```

领票晚于连接：**没有连接就没有「施工中」**。spawn 失败是同步返回（exec 错/秒退码）→ 立即换壳重起。

## 四种死法与事件源

| 死法 | 事件源 | 时钟 |
|---|---|---|
| 派了没起 | 结构消灭（先连后领）+ spawn 同步返回值 | 无 |
| 中途死 | 父进程 `SIGCHLD` + socket EOF（本机 socket 无需 keepalive，进程死即 EOF）——双源互证 | 无 |
| 活着但卡死 | **进度帧闹钟**（见下）+ **token 预算**耗尽 → 报 CTO 裁 | 兜底一处 |
| 编排器死 | 席位在独立 scope 不随死；编排器重启做**一次启动对账**：逐「施工中」行连其 socket，连上收养，连不上回队 | 无 |

### 进度帧

席位义务：每进入一个阶段推一帧（`调查 / 设计 / 写码 / 自测 / 提交 / 交付`，可带一句话）。编排器判「健康」的尺子是**距上一帧多久**，不是跑了多久。

- 闹钟缺省 30 分钟，随每帧重置
- 响了**不杀**：发「疑似卡死」事件给 CTO；CTO 读席位输出流判：真卡→杀+回队（换壳）；真在干→延期（重置闹钟并加大）
- 进度帧同时喂前端席位板——「施工中·自测」这一粒度就是业主要的「正在做什么」

### token 预算

每票挂预算上限（按角色缺省，CTO 可在票面覆盖）。壳适配层从壳输出流读用量，累计到阈值=事件：席位须交付或让位。预算是计数器，天然事件驱动，量的是真实成本；闹钟只是预算读不到时的兜底。

### 权限提示

壳全跑无交互模式。若壳流中仍出现「请求许可」帧，编排器自动答拒——席位要么绕开要么报错退出，不会挂着。

## 票相位

```
已立 → 设计中 → 已派 → 施工中 → 待审 → 审计中 → 待部署 → 部署中 → 完成
                  ↑         │                │
                  └── 回队 ─┘（席死/卡死/换壳）│
                  ↑                          │
                  └──────── 驳回（同壳重做）──┘
任一非终态 → 作废（CEO 令）
```

- 边表钦定，越边=拒
- 驳回 N 次（默认 3）→ 报 CEO
- 票只活在 DB；仓库里没有票面文件

## 部署闸（全无人，故全机械）

审计通过 → CTO 实例部署 → 三锚全绿才算完成：
1. 审计判决=通过
2. 项目配方的检查命令绿（如 O 的 check_all）
3. 部署后健康探针绿（项目配方定义）

任一红 → 自动回滚 → 报 CEO。

## 前端：席位板流

- 浏览器经 Connect（二进制 protobuf）订阅 `SeatBoard` 流
- 接入即发一帧：全席现态（角色/壳/模型/所领票/当前阶段/预算用量）
- 之后只推变化帧
- **不存历史**：业主只需知道现在，过去归 DB 审计面

## 壳健康

- 失效①②即标不可用，换壳
- 恢复不定时探——下一次有席位需要该壳时试一次（懒探）；成则恢复，败则跳过
- 每次标记/换壳/恢复 → 事件 → CEO
