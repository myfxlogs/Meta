## 八栏

### 1. 目标

四件一揽子：

1. **播报员引擎升级**（D-26/令#E13，连清 D-16）：`meta caster` 子命令＝AdminGateway
   客户端——水位游标回读 `ticket_event`＋textproto 路由表＋动作两类（通知／Dispatch）；
   `stall_suspect`→派 CTO 裁决席闭环（adjunct 席＋`SeatMsg.rule` 回流）；
   `budget_frozen`/`reject_limit`/`defer_limit`→通知（CEO 面预留）。
2. **断线补报**（D-25）：水位线文件＋启动/重连对账（`EventsAfter` 回读），零定时。
3. **注入按角色**（D-28）：`run/inject/<tid>-<role>.md`。
4. **配置化**（D-9＋D-27）：`GatewayConfig`/`RouteTable` textproto 出码外，
   帽值按毛口径校准（0003 实测 20.18M 起算）。
5. **审计派发径**（决策 40 补）：`待审` 票可派 `role=审计`（claim→`audit_start`→审计中）；
   审计判决 `Deliver.verdict` 回流——`pass`→`audit_pass`→待部署、`reject`→已派计驳回
   （自动重派施工）；`RetroVerdict` admin 令对滞留待审票（0003/0004）一次性机械回翻；
   审计席＝相位步行席（非 adjunct），用量双计入票级账。

### 2. 为什么

- 令#E13 钦定播报员二期：散落的「事件→必做动作」（stall→CTO 裁、三驳→CEO）缺机械消费者，
  路由表即电话簿；判断永不进播报员。
- stall 至今只在内部事件打转（D-16）：接上裁决席才成闭环；无 adjunct 型则裁决席必污染票相位。
- 播报员断线即静默漏报（D-25）；水位线让它「死而复生不欠账」。
- D-28 双席覆写是潜伏的相位门串行下炸点；D-9 硬编码登记表违「配置出码外」，
  D-27 按净值直觉定帽必被毛值击穿（0003 实证）。
- D-29：机器记录被过滤吃掉包行＝审计判据失真，本票起采集径改 raw。
- 决策 40：审计派发径提前并入——待审票滞留已实证（0003/0004），判决写径晚立一天，
  「交付未完」的假相就多积一天；边表早已钦定，缺的只是调用点。

### 3. 范围内

- **proto**：`RouteTable/Route/Action`（notify|dispatch 两型；`Route.note_contains`）；
  `GatewayConfig/RoleBudget/ShellRow`；`EventCursor`＋`AdminGateway.EventsAfter`；
  `DispatchReq.adjunct`；`SeatMsg.rule{action,note}`；`Deliver.verdict`（审计判决，
  审计必填 pass|reject，余角色必须空）；`RetroReq`＋`AdminGateway.RetroVerdict`。
- **`internal/caster` 新包**：表加载（未知动作/空 kind 拒）、水位文件（tmp+rename 原子写）、
  resync（EventsAfter 分页至短页）、notify 渲染+exec、dispatch 渲染模板→`Dispatch`、
  流断退避重连（1s→60s cap 无界，传输层语义）＋重连即 resync。
- **`cmd/meta` `caster` 子命令**：`--socket --routes --state-dir --run-dir --notify-cmd
  [--once] [--replay-history]`（水位文件缺失＝快进模式只推位不动作；`--replay-history` 显式追补历史）。
- **网关**：`transition()` 包装（相位门铃＋`reject_limit` 达 3 emit）；adjunct 派发
  （不走相位步行、必给 prompt_file、同票同角色活席去重、spawn 跳过 ResetAttemptUsage/
  warned 复位）与 claim/progress/usage/deliver/yield/dead 语义（设计 §1.3：
  usage 只计 used_total 不进 used）；`handleRule`（kill_requeue=failSet+killByGW+kill→既有
  回队径；defer=defer_count<K 才延期重挂，帽尽转 `defer_limit`）；`onStall` note 带
  run=`ActiveRunForTicket(adjunct=0)`；`EnsureBudgetDefaults`＋配置加载（`internal/config`，
  prototext，必载拒起）；`shellsFor` 种子改读配置；emit/append 顺序对齐（设计 §1.2 清单）；
  **审计派发径**（设计 §15 全量）：`DispatchSeat` 审计支（相位闸＝待审，不步行已派）、
  同角色活席去重（`ActiveRunForTicket` 查同 role 活 run→拒）、`specs` 键改 (ticket,role)、
  `handleClaim` 按 `run.Role` 选边（审计→audit_start，幂等相位＝审计中）、
  `handleDeliver` 审计支（verdict→audit_pass/reject；非法 verdict→InvalidArgument 不落相位）、
  `onRunDead` PhaseAuditing 支（audit_dead→待审不计驳回＋failSet 分级＋重派审计）、
  reject 后施工重派（内 `enqueueSpawn`＋`reject_count>0` 补 prefer＝最近施工壳名）、
  `RetroVerdict`（待审闸＋ref 必填＋audit_start→audit_pass|reject 两跳经 transition() 包装）。
- **`internal/db`**：`seat_run.adjunct`（schema+幂等 ALTER）、`EventsAfter`、`EnsureBudgetDefaults`、
  `IncrementDefer`、`Transition` 返回行 id、`ActiveRunForTicket` 排除 adjunct、
  `AddUsage` 增 `countAttempt` 形参。
- **`internal/seat`**：stdout 哨兵 `META_RULE:` 扫描→`SeatMsg.rule`；哨兵
  `META_VERDICT:pass|reject:<ref>` 同扫描点→`Deliver.verdict`＋`ref`。
- **`internal/gateway/inject.go`**：落盘 `<tid>-<role>.md`。
- **入仓文件**：`config/gateway.textproto`、`config/caster.textproto`（首批钦定行照设计 §2
  全文——含审计径新行：deliver→派审计、reject→重派施工、audit_dead→重派审计、
  audit_start/audit_pass→通知、spawn_needed＋note_contains 分角色）、
  `config/caster/stall-ruling.md`（裁决提示模板照设计 §5）；`scripts/events-caster.sh` 退化薄壳 exec。
- **`cmd/meta`**：新增 `retro` 子命令（`--ticket --verdict pass|reject --ref <判决档>`）。

### 6. 验收锚（全部机器可判）

1. `go build ./... && go vet ./...` 绿；`go test ./... -count=1` 绿；`bash scripts/selfcheck.sh` 绿。
2. **路由表**：`internal/caster` 表加载单测——fixture 全行解析成 proto；含未知动作/空 kind 的表→拒载。
3. **引擎**：resync 单测——伪 AdminGateway（内存实现）前置 `stall_suspect`/`budget_frozen`/表外 kind 三行→
   断言 Dispatch 一次（`adjunct&&role=="CTO"`，渲染后 prompt 含票号与 run 线索）、notify 两次、表外行零调用；
   `meta caster --once` 对种子库连跑两次→第二次零动作；推进后再插新行→只处理 `id>wm`；
   水位文件缺失首跑→快进模式：零动作且 wm 推进到现存最大 id。
4. **断线重连**：单测杀伪 Observe 服务端→引擎退避重连成功→间隙内落库的行被补处理（有界等待断言，非轮询）。
5. **stall 闭环**：helper 席新模式 `SEAT_MODE=rule`（attach+claim 后向流发 `Rule`）——
   kill_requeue→施工 run dead、票回 `已派`、failSet 含其壳键；defer→闹钟 deadline 后移≈ProgressTimeout、
   `defer_count=1`；第三次 defer→`defer_limit` 事件行且 count 不再增；
   非 adjunct 席发 rule→被拒（InvalidArgument/断流）；adjunct claim/deliver 不动票相位。
6. **三驳**：连续 3 次 `EdgeReject` 迁移（经 `transition()`）→`reject_limit` emit＋事件行各一；
   第 1/2 次无；dispatch 边迁移→`phase:dispatch` 门铃 emit。
7. **配置化**：serve 无 `--config` 且缺省路径无文件→拒起报路径指引；fixture 配置→shell 表按行落种、
   `EnsureBudgetDefaults` 写入角色帽；opencode 行 `attempt_cap` 在该行尝试上覆盖生效。
8. **D-28**：注入单测断言 `run/inject/<tid>-<role>.md` 生成；同票另一角色再注入→两文件并存不覆写。
9. **机器记录（D-29）**：交付的机器记录＝`go test -count=1 ./...` **原文**（禁 rtk 类过滤包裹），
   文件含 `^ok\s+meta/` 行数≥本次触及包数——审计按文件对账。
10. **对抗性锚（≥4，删/翻指定行测试必红）**：
    a. `process(row)` 中 `route.kind==row.kind` 等值比较（翻成 `!=`→表外 kind 也派单，锚 3 红）；
    b. adjunct claim 的「不转相位」早退分支（删→裁决席把票推离施工中，锚 5 红）；
    c. kill_requeue 里「施工壳键进 failSet」行（删→同壳重派不换壳，锚 5 红）；
    d. resync 的 wm 原子推进行（删→事件重复处理，锚 3 红）；
    e. `handleClaim` 审计支的 role→edge 分支（翻成统一 EdgeClaim→审计领票撞非法边，锚 11 红）；
    f. `handleDeliver` 审计支 `reject→EdgeReject` 映射（翻成 audit_pass→驳回票落待部署放行，锚 12 红）；
    g. `RetroVerdict` 第二跳 audit_pass/reject（删→票滞留审计中成「假审计中」，锚 13 红）。
11. **审计派发闸**：待审票 Dispatch(role=审计)→spawn→claim→`audit_start` 事件行＋相位
    审计中（`phase:audit_start` 门铃）；已派/施工中/审计中票派审计→拒；同票活审计席在
    再派→拒（同角色去重）；审计席 usage 帧→`used` 与 `used_total` 双增（票级账）。
12. **判决回流**：helper 席 role=审计 `SEAT_MODE=verdict`（claim 后 Deliver{verdict}）——
    pass→待部署（`audit_pass` 行＋门铃）；reject→已派（`reject` 行＋`reject_count=1`）
    ＋票上出现 role=施工 的新 run（重派发生）；verdict 非法/缺→InvalidArgument 且相位
    不动；杀审计席→待审（`audit_dead` 行，`reject_count` 不变）＋重派审计 run 出现。
13. **回翻件**：种子库待审票 `meta retro --verdict pass --ref <档>`→`audit_start`＋
    `audit_pass` 两行落账（actor=admin、note 含回翻与 ref）＋相位待部署；非待审票→拒；
    ref 空→拒；二次调用→拒（幂等）；`--verdict reject`→已派＋`reject_count=1`。
14. **审计径路由**：fixture 新行全解析；伪 AdminGateway 喂 `deliver` 行→捕获
    Dispatch{role=审计, prefer=claude, prompt_file 空（注入径）}；`spawn_needed` 行 note
    「对账补发: 审计/施工/CTO」三行→审计、施工各一派、CTO 零调用（表外不动作）。
