# 票 24：小债扫尾＋无头CEO路由（CTO 执行票——对账→设计→立票带 spec→派发→已派清单）

> 任务令源＝决策 76 续·扫尾票（CEO 注入需求）＋决策 77 追加指令（最高优先
> 一件：无头 CEO 触发路由）。清单：D-36（GetBudget err return，优先）/D-22/
> D-34/D-37/D-19·20/D-38+D-14/D-5/D-15/D-18/D-6＋追加件，可拆 1–3 张票，
> 照 0008 先例自拆自派。

> 票备案形制），经 `META_ADMIN:fill_spec` 回填。

### 1. 目标

1. 对账十一笔债→分「已清待销号」与「真在账」：D-36/22/34/37/15/14/38/5
   八笔经票-0011（及 t0004/12/15）判决档与现码实证已清（不重复立票）；
   D-19/20/18/6 四笔真在账。
2. 决策 77 追加件：调查＝`deploy_failed` 一行 seed 缺失＋四类钉锚（机制
   `ceo_spawn_kinds`/`ensureCEO`/`ceo-headless.md` 俱在——补线非新机制）。
3. D-18/D-6 出设计裁定（修／AST 闸＋staticcheck 不引）。
4. 设计档 `docs/实现/设计-0024-债务扫尾批.md` 落仓 commit。
5. 拆子票 `26`（追加件·最高优先）/`27`（四件扫尾），八栏 spec 经
   `META_ADMIN:create_ticket` 入 DB。
6. 预制施工 worktree ×2，`META_ADMIN:dispatch` 按 26→27 序派发；stdout
   报已派清单＋各债归属。

### 2. 为什么

- 决策 76：债无自愈、打包走正常流水；每完成一批即开下一批——捎带是慢漏，
  批清是止损。
- 决策 77：坏消息只通知不派化身＝自抓率主缺口；deploy_failed 是两列种子
  唯一的缺席者（其余五 kind 已在列但无回归锚）。
- 八笔已清债的核销凭据须机械可复算（E7：凭判决档销号，无判决指向的销号
  无效）——逐笔给码位＋测试名＋引入票号。
- D-18 原债留「按 run 键分账属设计层」待裁；D-6 留「是否补 staticcheck
  类机械闸」待裁——本票裁定落档。
