# 票 26：无头 CEO 触发路由补线——deploy_failed 入化身判决域＋四类钉锚

> 票面（施工输入）；经 `META_ADMIN:create_ticket` 入 DB 后派发。
> 设计全案＝`docs/实现/设计-0024-债务扫尾批.md` §2.1（支 c/0024-design）。

### 1. 目标

完成决策 77 追加件：`deploy_failed` 补入 `ceo_spawn_kinds` 与 `ceo_events`
两列（`config/gateway.textproto`）——部署失败已回滚的坏消息与
reject_limit/budget_frozen/shells_exhausted 同规：有 CEO 连接随流派发、
无连接经 `ceoPending`＋`ensureCEO` 起无头化身自裁。四类＋defer_limit/
feishu_inbound 的种子集全部钉测试锚；`ceo-headless.md` 先读节补部署失败
专行（先核回滚态，D-2）。

### 2. 为什么

- 决策 77：坏消息只通知不派化身＝自抓率主缺口（本该化身干的活在终端 CEO
  身上）；「每个新病只疼一次」要求坏消息入化身判决域。
- 机制俱在（`ceo.go:94-123` 消费环＋`136 ensureCEO`＋`ceo-headless.md`
  模板），唯 `deploy_failed` 两列皆无——决策 72/73 部署死结实证：部署
  失败滞留时无化身接裁。
- 既有五 kind 的种子行无回归锚（纸面风险——决策 71 条款级验证规矩）：
  本票把六行种子全钉死。
- caster 侧 `Dispatch(role=CEO)` 经 SeatAdmin 硬拒（禁区#10）——正解是
  网关内 `ceo_spawn_kinds` 触发列，非路由表加 dispatch 行（设计 §2.1 裁定）。

### 3. 范围内

- `config/gateway.textproto`：`ceo_spawn_kinds:` 与 `ceo_events:` 两列
  各补一行 `deploy_failed`（既有六行一字不动）。
- `config/caster/ceo-headless.md`：`## 先读` 节补一行部署失败专径——
  「kind=deploy_failed：先核回滚态——`meta events --ticket <id>` 看
  deploy_failed 行 note 与前任 run、`meta runs --ticket <id>` 看部署席
  执行记录（exec-resp/rollback 步），回滚态未核不裁重试（D-2）」。
- `internal/config/config_test.go`：新增 `TestProdGatewayConfig_CeoKinds`
  ——`Load("../../config/gateway.textproto")` 断言六 kind
  （reject_limit/budget_frozen/shells_exhausted/deploy_failed/defer_limit/
  feishu_inbound）在 `CeoSpawnKinds` 与 `CeoEvents` 两列同时在。
- `internal/gateway/ceo_test.go`：新增 `TestCeoSpawn_DeployFailed`——
  emit `deploy_failed` 事件无 CEO 订阅→`seat_run` 出现 role=CEO run＋
  `ceoPending` 曾含该事件（复用 `TestCeoSpawn` 骨架换 kind＋断言 pending）。

### 4. 范围外（禁线）

- `config/caster.textproto` 路由表一字不动（notify 行原样；`dispatch` 动作
  不加 CEO——SeatAdmin 径硬拒是禁区#10 钦定闸）。
- `ceo_spawn_kinds`/`ceo_events` 既有行不增删；`defer_limit`/`feishu_inbound`
  已在列仅钉锚。
- `ensureCEO`/`ceoPending`/锁/泵机制代码零改动（机制已验，本票补 seed 与锚）；
  `DispatchSeat` role=CEO 拒径不动。
- proto/schema 不动；不引依赖；不加定时器；不部署不并 master。
