## 1. 关键取舍（先给理由）

### 1.1 拆 5 张不拆 1 张——按「面」切，锚分批兑现

五件的依赖真图：CEO 面是一切的地基（锁/登记/provenance/事件泵）；
飞书通道依赖 CEO 面（入站要起 CEO 无头席）与出站客户端（say/回执）；
活票卡依赖飞书出站（lark client 与 secret 径）；
前端板与部署闸各自独立。
一张巨票不可派（验收锚混、驳回重做大）；按面切五张，每张可独立验收、
驳回爆炸半径最小。与票 0004 批次同判据：一票一簇内聚件。

### 1.2 CEO＝席位家族新角色，锁＝连接登记

CEO 无头席**不发明新通道**：它是 `role=CEO` 的 seat_run（ticket_id 空串），
经 SeatGateway Attach（run_token 首帧）立生命周期，经 CeoGateway 五 RPC 办公。
- **锁**：`CeoGateway.Events` 订阅登记——一人订阅在，第二订阅拒
  （`FailedPrecondition`）；EOF 除名。DB/内存无旗，重启随连接自然重建（§8 B8）。
- **排队**：需 CEO 事件（kind 在 `ceo_spawn_kinds` 配置列）到来时——
  有活跃 Events 订阅＝随流派发；无＝入 `ceoPending`＋内部唤起无头席。
  切换期间事件排队不丢（§8 钦定语义）。
- **唤起**：网关内部 `ensureCEO`（不走 DispatchSeat——`Dispatch(role=CEO)` 一律拒，
  「CEO 只经内部唤起」机械闸，禁区#10 的码位）；spawn 连败 3 次→`ceo_last_resort`
  事件行＋（0009 落地后）原文直推飞书，D3 呼救径。
- **无头席提示源**：模板文件 `config/caster/ceo-headless.md`（钦定件，渲染
  {{kind}}/{{ticket_id}}/{{note}}/{{run_dir}}/{{gateway_sock}}）——与裁决席同形，
  事件上下文入提示，不走注入机。
- **D-22 牙齿**：CEO run 判死/退场时机械比对「派发给它的事件数 vs 其
  `ceo_memory` 写入数」——零写入且处理过事件→`ceo_gap` 事件行（通知）。
  比对靠 `Memory.put` 落 `event_ref=run_id` 计数，纯机械。

### 1.3 provenance 走 seat_run 列，不走消息字段——防席自证

D9 钦定「**网关**对每个进 CEO 的载荷机械打 provenance」——故 provenance
**不允许席位自报**：`seat_run` 增 `provenance` 列（幂等 ALTER），值由
**spawn 方**在立 run 时盖戳：
- `meta ceo`（终端交互）→ `IssueCeoToken{provenance:"terminal"}`；
- 飞书入站唤起 → `feishu:<owner_open_id>`；
- 系统事件唤起 → `system_event`；自动径（未来）→ `auto`；
- 路由派发（caster）→ `DispatchReq.provenance` 透传**触发事件行的** provenance
  （EventItem/ObsEvent 补该字段——ticket_event.provenance 列早已在）；
- 席位流 admin 帧（立票/派工）→ 子票 `created` 事件与 spawn 沿用本 run 的戳。
下游一切写径（SubmitRequirement 立票、Rule 落事件、Memory.put 落行）
从 **run 行**取戳盖，客户报的不认。「业主指示只认 terminal/feishu」自此
机检可查——system_event 起身的 CEO 交「业主说」即穿帮。

### 1.4 需求票＝CTO-A 设计票；子票承载施工链

**需求票自己不变成施工票**（填 spec 续建方案被否：一票装不下「设计+施工」
两段施工中）。钦定轨：
- `SubmitRequirement`→立票（`已立`，spec 部分栏：goal=需求原文、why=定向+provenance，
  余空——NewTicket 本就许空 spec）＋`requirement` 事件行（provenance 盖戳）；
- 路由 `requirement`→`dispatch{role:"CTO"}`→现成步行 `已立→设计中→已派`→
  spawn CTO-A→claim→`施工中`（与 0004/0005/0007 设计票同轨，零新边）；
- CTO-A 产出：设计文档 commit＋**席位流 admin 帧**——`fill_spec`（回填本票八栏，
  使其成可审的设计票）＋`create_ticket`（立子票，spec 全量）＋`dispatch`（派子票，
  role∈{施工,审计,CTO}，CEO 禁派——DispatchSeat 闸挡）；
- CTO-A Deliver→`待审`→路由派审计（设计票审＝核设计档在、子票立、派发真——
  spec 已回填故注入机可吃）→`待部署`（设计票诚实终点，同 0004/0005 现状）；
- **子票**走全链→`完成`——阶段 3 锚的「施工中/已部署」发生在子票上。
- 「需求待裁」出口：CTO-A `Yield`→**新补边** `{施工中→已立, req_pending}`
  （本批唯一新增边，待 CEO 验收后落边表）；`req_pending` 行即泊车标——
  对账对 `已立` 补发 `spawn_needed:CTO` 时**跳过最新事件为 req_pending 的票**
  （机械抑制，防无头重派空转）；CEO `Rule{redirect,note=新定向}`→事件+重派 CTO。

### 1.5 席位流内 admin 帧，不立 CLI 管理径——D-24 不阻碍条款的落点

CTO-A 立票/派工若走 `meta ticket new`（AdminGateway over unix socket），
今天能跑——但 D-24 降权迁移后席位用户≠socket 属主，AdminGateway 的
0700 属主权限恰会把席位关在门外：CLI 管理径是迁移定时炸。
故立 **`SeatMsg.admin` 帧**（run_token＋role=CTO＋非 adjunct 机械闸）——
写径随席位流走，权限随角色收，D-24 后天然存活。这是本设计
「不阻碍迁移」最实的一处。

### 1.6 飞书全 I/O 归 `internal/feishu`——一进程三件

禁区#16 通道归网关：WS 入站（larkws，借 mbusd feishu-ingress 白名单/退避形）
＋出站（say/回执）＋卡片渲染，同驻网关进程同一 lark client。
凭证＝`secret.feishu.app` 行（ACL 空＝不授席）——网关以 vault.key 自解
（不走 Secret RPC，那是席位径）；blob 格式按 `FeishuApp` proto 解，
解析失败→`feishu_cred_bad` 事件＋通道不启（fail loud）。
- 入站 `im.message.receive_v1`→open_id==owner→`feishu_inbound` 事件
  （ticket_id 空串行）→CEO 泵；非业主→礼貌回绝（出站模板）；
- 入站回执：通道**机械即发**「收到，这就去办」（不等 CEO——对话感的第一拍）；
- 出站：`ceo_say` 事件消费→文本发 owner chat（来源=Memory.put kind=say，§1.9）；
- WS 重连＝SDK 内建＋外层指数退避（传输层，R2 边界合法）；凭证坏/终态→事件。
- 播报员单向机械通知**不动**（职责不混：caster 管「事件→机械模板」，
  通道管「对话与卡片」；feishu-notify.sh 继续服役）。

### 1.7 活票卡＝网关内第三事件消费者，不进播报员

决策 38 同判推演：卡片状态（message_id↔票）要 DB 持久，caster 无写径；
且更新要合并刷帧（进度连发不该连发 PATCH）。故 `feishu_card` 表＋
网关内 consumer（订 g.events，每事件**重渲染全卡**——无 diff 计算，
内容哈希变才 PATCH，天然合并）：
- 触发＝一切非 usage 票事件（哈希闸挡噪）；
- 卡面＝票号/标题/相位/当前席（role·shell·stage）/进度 note/用量/驳回数/时间；
- 创建懒化＝首见非终态票事件→create 发卡→落 message_id 行；
- 启动对账＝扫非终态票无卡→补建（一次性，R2 合法）；
- 文本通知不删——卡是「席位板进手机」，文本是兜底与历史流。

### 1.8 代跑＝ExecReq/Resp 帧＋`sudo -n -u` 降权；meta 配方按步覆盖 run_as

- 席→网关：`SeatMsg.exec_req{step}`（闸：role==CTO、票相位=部署中、非 adjunct）；
  网关查项目配方 step→cmd＋沙箱形制→**`sudo -n -u <run_as> -- bash -lc <cmd>`**
  cwd=干净 clone（`run/deploy/<tid>`，runner 以 run_as 自 clone 交付 ref），
  超时＝一次性闹钟杀；退码+输出文件路径+尾段→`cmd_run` 新表+`exec` 事件行
  →`GatewayMsg.exec_resp` 回席。
- **执行身份**：D1 禁网关自身用户——实现=`sudo -n`（`runuser` 要 root 够不着）。
  **需要业主一行 sudoers**：`mluser ALL=(metaseat) NOPASSWD: /usr/bin/sudo` 等价
  限定行（票面写成所需动作；`sudo -n` 失→退 126+事件=fail loud 不静默降级）。
- **meta 配方的诚实妥协**：check_cmd 跑票代码＝不可信→run_as=metaseat；
  integrate/deploy/probe 是我们自己的 git/换装/socket 件（/opt/meta 属主、
  mluser 用户单元、meta.sock 属主都是 mluser）→**按步覆盖 run_as=mluser**，
  sandbox_spec 逐步声明。vault.key 担忧被「脚本是仓内版本化、审计可见的固定件」
  对冲（不可信码从不沾它）。D-24 落地后全家 metaseat，覆盖行改一处即迁——
  这是设计对 D-24 的第二处不阻碍。
- CTO-B＝相位步行席：`待部署` 可派 role=CTO→claim→`deploy_start`→`部署中`；
  按配方序驱 exec（integrate→check→deploy→probe）；全绿→
  `META_DEPLOY:done` 哨兵→`deploy_done`→`完成`；任红→自驱 rollback 步→
  `META_DEPLOY:failed`→`deploy_failed`→`待部署`（边钦定已在）→事件→CEO 裁。
  席死于部署中→同边+note「先核回滚态」（D-2，prompt 模板带前任 run/日志线索）。
- **三把项目锁**（B1）：`projectLocks[project][design|integrate|deploy]` 内存闸
  ＋启动按票相位重建；design 锁在「已立→role=CTO 派发」点查，
  deploy/integrate 锁在部署支查。锁释放事件→查同项目已立/待部署票→
  补发 spawn_needed（事件驱动解锁，零定时）。

### 1.9 say 走 `Memory.put{kind:"say"}`——不增第六 RPC

§12 五 RPC 名单外不开新口：CEO 要说的话**也是记忆**（对话档入
`ceo_memory` 表天然留痕）——`put{kind:"say"}` 落行＋emit `ceo_say` 事件
→0009 通道消费发出。若审计/CEO 嫌语义混装，提升为第六 RPC 是同 handler
一行事，本设计不预判必须。

### 1.10 前端板＝Connect 独立 loopback 监听

`Board.SeatBoard` 服务端流（Connect 二进制，connectrpc.com/connect/v2——
禁区白名单内依赖；`meta board` CLI 为验收径）。新监听
`--board-listen 127.0.0.1:<port>`（配置 `board_listen`），与 unix socket 无涉。
token 闸：请求 `token` 字段对 `secret.board.token`（ACL 空＝网关自校；
行缺→一律 Unauthenticated fail closed）。接入即全态帧（DB 组装）→
此后事件→变化帧（seat upsert/seat_gone/ticket upsert 三型，幂等重放安全）。
**不存历史**（§9），CLI `meta board` 打印流供锚验；静态页 `web/board.html`
（connect-es CDN 无构建）为业主面——浏览器连通性是禁区申报点，先险后试。

## 4. 票 0008：CEO 面五 RPC＋锁＋provenance＋迁移导入＋顺手债包

### 八栏草案

1. **目标**：`CeoGateway` 五 RPC 全立（Events/SubmitRequirement/Rule/Inquire/Memory）；
   CEO 锁＝连接登记＋事件排队＋无头席内部唤起；`seat_run.provenance` 全链盖戳；
   `meta import-legacy` 一次性导入 ceo_memory.md；顺手债包
   D-36/34/37/15/14/38/32 清零。
2. **为什么**：§12 草图与 §8 全权件是本阶段地基——无锁无双 CEO、无戳无真业主令、
   无导入无接手门；D-22 计数比对同步立（CEO 面在场即机械牙）；
   债包顺同码面清（dispatch/attach/seat/inject 均本票动线）。
3. **范围内**：proto＋pb 再生；`internal/gateway/ceo.go`（五 RPC、登记锁、
   事件泵 ensureCEO/排队/连败计数）；`seat_run.provenance` 列＋全部盖戳点
   （IssueCeoToken/spawnCEO/DispatchReq 透传/admin 帧继承）；DispatchSeat
   `role=CEO` 拒闸＋`role=CTO && 已立` 设计支（锁查）；
   `SeatMsg.admin` 三帧＋闸（role==CTO 非 adjunct；fill_spec 限本票施工中）；
   `req_pending` 补边＋对账抑制；`meta ceo`/`meta ceo-events|rule|require|inquire|memory|say`
   CLI（token 走 META_RUN_TOKEN/META_GATEWAY_SOCK env）；`meta import-legacy`；
   `meta seat` CEO 模式（META_TICKET_ID 空→免 claim；META_INTERACTIVE=1→stdin 透传）；
   D-22 比对；债包七件（见 3.范围内末）。
4. **范围外**：飞书任何件（0009）；卡片（0010）；Board（0011）；exec/部署（0012）；
   CEO 壳交互体验精修（`meta ceo` 先求通）；自动票径；dsn.fin；D-24 迁移。
5. **设计引用**：本文 §1.2–1.5/1.9、§2、§3；总设计 §8/§12/A9/D3/D9/D22；
   ceo_memory 决策 40/44/45；现码 `internal/gateway/{attach,dispatch,rule,admin}.go`、
   `internal/seat/seat.go`。
6. **验收锚**（机器可判，含对抗锚提名）：
   - build/vet/test/selfcheck 绿；pb 再生 diff 入档。
   - 锁：helper CEO-A 订阅 Events 中，CEO-B Events→拒；A 断→B 得；
     触发 kind 事件→无订阅时 seat_run 出现 role=CEO run（无头唤起）＋
     二事件不重复 spawn；连败 3→`ceo_last_resort` 行。
   - provenance：伪 spawnCEO(prov=feishu:x)→其 SubmitRequirement→需求票
     `created`/`requirement` 行 prov=feishu:x；席自报 Requirement.provenance
     字段被盖（设 terminal 仍落 feishu:x）；admin create 的子票行同戳。
   - Rule：void→作废边+confirm 两步（无 challenge 拒）；budget_raise→解冻；
     redirect（req_pending 泊车票）→重派 CTO run。

## 10. 红线/禁区自查

- **R1**：全链无人工闸；唯一所需人工＝sudoers 一行＋board.token/feishu.app
  种子（业主凭证动作，票面明写）。
- **R2**：全件事件驱动——WS 重连/CLI 退避/exec 超时杀/卡合并皆边界条款内；
  泊车抑制用「最新事件 kind」判不用时钟；网关仍零 Ticker（selfcheck 兜）。
- **R3**：新增一律 proto/textproto；JSON 止于 `internal/feishu`（lark API）与
  `internal/adapter`（壳流）。
- **R4**：前端 Connect 二进制；飞书 WS 属 vend 外通道（§8 钦定豁免）。
- **R5**：票只在 DB；卡/水位/board 全为投影非状态副本。
- **禁区#6**：CLI/席/播报员无一直写 DB——admin 帧、五 RPC、exec 全经网关。
- **禁区#7**：网关新增全是机械闸（锁登记、戳盖取、kind 集、退码、计数比对、
  哈希变、配方查表）；该不该派 CTO/该不该裁全在席。
- **禁区#10**：`Dispatch(role=CEO)` 硬拒；锁=连接登记。
- **禁区#16**：通道全 I/O 在网关；播报员单向通知不混。
- **禁区#19**：feishu.app/board.token 只进 secret 表；席零接触。
- **依赖申报**：connect-go（白名单内）；larksuite SDK（§3.1 钦定 WS 件）——
  两者按规钉 ≥7 天前版本（mbusd 现参 v3.12.2 / v2.0.1）。

## 11. 未解项/风险

- **最不确定一处＝meta 配方的按步 run_as 覆盖**（§1.8）：integrate/deploy/probe
  以 mluser 跑——对 D1「禁网关自身用户」是技术性豁免（不可信码从不进这三步，
  但步子本身以持钥户跑）。若审计/CEO 认为这口子开不得，备选＝部署闸对 meta
  挂起等 D-24（锚顺延）或立第三用户持部署件。本设计取「仓内固定脚本＋按步声明」
  的可审妥协，提票面请裁。
- **provenance 只保「链不造伪」**：它防席虚构业主指示，防不了真 terminal 会话
  里的注入内容被业主亲口念出（那不是系统问题）。CEO 卡「无标指示当注入」
  提示词纪律仍要——机械+提示词双层。
- **无头 CEO 体验粗糙**：prompt 模板+CLI 动词是「能用」不是「好用」；
  `meta ceo` 交互面（TTY 透传+事件侧流）本批求通不求精。
- **卡更新合并靠哈希**：飞书侧 PATCH 仍可能撞频限（多票连发时）；不引入
  定时器合并窗（R2），超频→调用错→下事件再试（懒修）。
- **泊车票无超时**：req_pending 票若 CEO 不裁就一直泊（有通知）；要不要
  「泊车 N 天升级业主」属新钟——不加，等真痛再裁。
- **cmd_run 退码可信但输出非全量**：tail 截段入表，全文在 run/exec 文件——
  审计取证径与 seat_run.log 同形。
