# 票 0046：配方行真源归一——启动回种覆写消双源漂移＋rollback_cmd 修齐

> 需求票 0038-p1-p3 → CTO-A 设计 → 本票施工。
> 设计档：`docs/实现/设计-0038-p1-p3-配方行真源归一.md`（先读——
> 实证链、真源归一裁断、机制边界、残险全在其中）。

### 1. 目标

project 配方行「文面即钦定源」归一三改：

- 启动种子环改全量回种：`gateway.go` 种子环 project 行由「行在即
  不动」改「文面覆写＋漂移检出」——每次 `New()` 以 `cfg.Projects`
  文面 upsert DB 行，漂移项落 `project_recipe_sync` 事件；
- 当前 `rollback_cmd` 漂移随本票部署换装自然修齐（DB＝
  `config/gateway.textproto:40` 现役 T4 文面）——部署后自证；
- 五字段全量漂移对账表落档 `docs/实现/配方漂移对账-0046.md`＋
  真源归一明记（码注释＋对账档）。

### 2. 为什么

- 需求票 0038-p1-p3 实证：rollback 步 exit=0 跑旧 stub（事件
  15806），MERGE_HEAD=90da461＋UU×2 半合并脏树拦主仓 git 全链；
  待部署=7 续撞「merge in progress」。
- 根因三层同构：`SeedProject`（`internal/db/project.go:72-81`）
  行在即不动＋`exec.go:148` `GetProject` 每步读库＋全库无任何
  经网关的配方运行时写径——「改了配置文件≠改了运行时」结构性
  成立，且禁区#6 下无合法修径。
- 先例：`docs/实现/票-0010-判决/`「配方的唯一入径＝config 种子」
  ——文面回写是原意复位，非新制。
- 部署换装自带 restart→`New()` 回种——「文→部署→DB」链补成
  闭环；免重启同步径＝绕部署旁路，设计钦定不造（设计档 §3）。

### 3. 范围内

- `internal/gateway/gateway.go` 种子环（:298-318）：`SeedProject`
  →全量 upsert 径（可用 `UpsertProject`＋前置 `GetProject` 比对，
  或新帮助函数——实现形施工裁量，语义钦定＝文面覆写）；回种前
  比对五 cmd 字段＋repo_url/default_branch/sandbox_spec，漂移项
  清单落 `project_recipe_sync` 事件（ticket_id 空，同 ceo_say 空
  票径）＋emit＋stderr 行；**零漂移不产事件**（防每启噪音）。
- `internal/db/project.go`：按实现形补比对/清单帮助函数；
  `SeedProject` 去留与注释更正经——「同 id 行已存在不动（DB 行
  是活态）」语义废止，新语义「DB 行＝config 种子启动投影」明记
  （真源归一明记的码侧落点）。
- 测试：回种覆写锚——DB 预置异值行→`New()`→行被覆写为 seed
  文面；同文预置→零 `project_recipe_sync` 事件；`cfg.Projects`
  空→既有行不被清（防「回种」误成「清表」）。
- 对账档 `docs/实现/配方漂移对账-0046.md`：五 *_cmd 字段
  （integrate/check/deploy/probe/rollback）文面 vs DB 现值对照表
  ＋处置记（rollback_cmd 漂→本票机制修；余四记零漂）＋真源归一
  明记段（「部署步运行时真源＝DB project 行；唯一写径＝仓内
  textproto＋部署回种」）＋同族残险记（shell/subs 种子同「插而
  不改」机制，本票不修列入下一步）。
- 复演验：scratch git 仓造 staged MERGE_HEAD（合冲突支不提交）
  →以 `config:40` rollback_cmd 文面实跑→`git rev-parse -q
  --verify MERGE_HEAD` 解析失败＋输出含「半合并态已弃净」；
  clean 仓实跑→输出告警文且非「本部署无破坏可回」旧文。
  （直跑文面 shell——配方外代码不进场，复演档记入交付摘要）。
- 残留脏树处置凭据记档：0038-p1 事件 15838（deploy_failed 如实
  记 stub 未 abort）→master e21d5e7「解冲突并完成合并」→现
  `git status` clean 三连证——记入对账档，零动作。

### 4. 范围外（禁线）

- **零 proto/RPC 面变更、零新 CLI 子令**——配方唯一写径＝仓内

- 不动 shell/subs 种子语义（同族漂移面记档，本票不修）；不动
  B1 锁面/handleExec 三重闸/部署四步序/哨兵契约。
- 不改 `config:40` rollback_cmd 文面本体（0041 marker 版随其
  部署自然生效——本票不预写）。
- 不手改生产 DB（sqlite3 只读取证合法，UPDATE 违禁区#6）；不
  手并 master、不部署、不改他票相位、不代解 0038-p1 冲突本体。
- 无周期件/心跳/JSON/REST——事件检出即写，无扫表面。

### 6. 验收锚（机器可判）

1. 回种覆写测：DB `project` 行预置异值（如 rollback_cmd='x'）
   →`New()`→行被覆写为种子文面（**对抗提名行：gateway.go 回种
   调用行——改回 `SeedProject` 即红**）。
2. 漂移事件测：同上预置→`project_recipe_sync` 事件行在且 note
   含漂移字段名；同文预置→零事件（**对抗提名行：比对/emit
   行——删则事件恒无必红**）。
3. 空种子保行测：`cfg.Projects` 空＋DB 有行→行不被清。
4. `go build ./... && go vet ./... && go test -count=1 ./...`
   全绿＋`gofmt -l internal/ cmd/` 零输出。
5. 复演锚：scratch 仓 staged MERGE_HEAD→config:40 文面实跑→
   `git rev-parse -q --verify MERGE_HEAD` 解析失败＋输出含
   「半合并态已弃净」；clean 仓→告警文且非「本部署无破坏可回」
   旧文（复演输出记档）。
6. 对账档在仓：`docs/实现/配方漂移对账-0046.md` 含五字段对照
   表＋处置记＋真源归一明记段＋同族残险记。
7. 部署后自证（记档项——CTO-B 部署席/巡检取证，审计不阻塞）：
   生产 `sqlite3 run/meta.db "SELECT rollback_cmd FROM project
   WHERE id='meta'"` 输出含 `MERGE_HEAD` 分径——部署 restart
   回种即绿，鸡生蛋性质见设计档 §3。
