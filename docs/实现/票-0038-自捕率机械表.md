# 票 0038：自捕率机械表——事件驱动重算并上卡

> 立票：CEO（终端形态）·决策 90·2026-11-02。决策 77 落地：自捕率基线 10%、
> 目标 ≥90%，至今纸面无度量。对标 super-agent 的 benchmark 文化——我们自己
> 的排行榜，业主看卡即见趋势。零新时钟（R2）：只在事件到达时重算。

### 1. 目标
每次审计判决（含驳回）与部署结果事件触发自捕率重算，滚动指标上运维卡新行
「自捕率：X%（近 20 判）」；纯事件驱动，禁 cron。

### 2. 为什么
「自捕率」是本项目自主度的核心指标（业主北星：不需要外部检查或催办）；
无机械度量＝纸面指标＝永远停在 10%。super-agent 拿榜说话，我们拿卡说话。

### 3. 范围
- 口径（先写死进卡 tooltip/附注，可后调）：**外捕**＝审计驳回、部署失败、
  巡检立案三类事件；**自捕**＝施工/部署自报坑档（坑档：同生标签）且同票
  后续未因同类问题被驳。分母＝近 20 判（外捕+自捕判例流）。
- 计算挂既有事件消费者（卡视图装配处或 caster 消费端，施工定夺并记因）。
- 数据源＝`ticket_event` 行分类统计（读行不写行）。
- 卡渲染：E14 卡体系加一行；单测含事件重放幂等（同事件不双计）。

### 4. 禁区
- 定时器/轮询/快照表（R2）；历史全量回填（另票）；多项目分表。
- `ticket_event` 手工 INSERT（D-56）。

### 5. 引用
决策 77、决策 90、E14；`internal/feishu/card.go`、`internal/gateway/
feishu_card.go`（卡装配）；`internal/db` 事件行读取。

### 6. 对抗锚
- 注入一拒判事件→卡自捕率必变且方向正确。
- 同事件重放→数值不变（幂等）。
- 无判例流→行显示「暂无」不显示 0%。

### 7. 验证
build/vet/test/selfcheck 四件＋事件注入演练实证档（拒判前后卡对照）。

### 8. 交付
口径说明（入卡附注）＋计算件＋卡行渲染＋单测＋演练实证档；不部署。
