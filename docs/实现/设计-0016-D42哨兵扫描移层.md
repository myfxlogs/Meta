## 1. 需求原文与现状确诊

**需求**：判决哨兵（`META_VERDICT`/`META_DELIVER`）在 claude/opencode 的
JSON 流壳里被包进字符串，外壳「独立一行扫原始 stdout」永不命中——判决全丢；
devin 纯文本壳偶发丢失一并查。修法方向（决策 60/63 钦定）：**扫描点移到
适配器解析后的文本流**（壳无关）。

**确诊**（逐条指到机器证据）：

| 事实 | 落点/证据 |
|---|---|

## 2. 总体方案：双机制＋双发契约

**机制一（钦定方向）：扫描点移到适配器解析后文本流。**
`adapter.Frame` 增全文字段 `Text`；seat 对每帧 `Text` 按 `\n` 切行逐行过
哨兵匹配器——壳解析差异仍止于 adapter 包（禁区#3），seat 只见文本流。

**机制二（devin 行合并的根治通道）：`$META_ART_DIR/sentinel.log` 文件兜底。**
契约改「哨兵双发」：席位每条哨兵 **stdout 独占行 + 原文追加
`$META_ART_DIR/sentinel.log` 一行**。seat 事件驱动增量读（见 §3.3）——
文件写径旁路一切壳渲染（合并/包裹/截断全免疫）。先例同构：
`$META_ART_DIR/exec-resp.log`（票0010 META_EXEC 回执径）。

**为什么不用 substring 扫描救 devin 合并**：哨兵载荷无自闭界——
`META_DELIVER:<路径>粘文` 中 ref 边界不可机判（CJK/路径/粘文同字符域），
且行中旁注「尾带 `META_DELIVER:x`」会成伪命中。行首锚定不可放。

**为什么文件源值优先**：流源行可能被粘文污染（devin 型），文件行是席位
直写原文——同种哨兵文件一旦落值，流源不再覆盖（见 §3.4）。

## 3. 落点明细

### 3.1 adapter 包：Frame 全文面

`internal/adapter/adapter.go` `Frame` 增字段：

```go
Text string // 全量解码文本（可多行）；Note 仍为 ≤200 预览不变
```

各适配器赋值：

| 适配器 | Text 来源 |
|---|---|
| claude | `assistant` 文本块→`p.Text`；`result`（含 is_error）→`m.Result`；不可解析行→**原行全文** |
| opencode | `text`→`m.Part.Text`；`error`→`m.Part.Message+m.Part.Reason`；不可解析行→原行全文 |
| devin | 原行全文（透传本性不变） |

不改 `Parse` 签名、不加接口——结构体增字段，调用方零破坏。
**扫描域界定（防自吞/伪吞）**：只扫 FrameText/FrameResult/FrameError 帧的
`Text`——claude 的 `tool_use` 输入（判决档 Write 自带哨兵行）、`user`/
`tool_result` 事件、`thinking` 块均不出 `Text`，不扫。

### 3.2 seat：扫描点移位（`internal/seat/seat.go`）

- 删除循环内 `s.scanSentinel(l)`（原始行调用）。
- 循环内每帧：取 `fr.Text`，`strings.Split(text,"\n")` 逐段
  `scanSentinel(seg, srcStream)`——行内语义不变（`TrimSpace`+`CutPrefix`），
  `\r\n` 尾由 `TrimSpace` 自然消化；**行中提及不命中**（保「单独一行」）。
- 哨兵行被消费后不再算活性文本（与旧契约「哨兵行不进适配器」同义的
  新表述＝「哨兵段不进活性计数」）；未命中段仍属活性。
- 缓冲：`sc.Buffer` 1MB→16MB（同失明族顺手修）。

### 3.3 seat：sentinel.log 文件兜底泵

- 读点（全事件驱动、零定时器，R2 合规）：①每处理完一条 stdout 行后
  泵一次 ②`cmd.Wait()` 返回后（净退闸判之前）泵一次。
- 增量读：offset 跟踪、只处理 `\n` 收口的完整行，尾残段留下次——
  文件小（条数级），成本 O(增量)。
- 文件缺失/空＝零成本路径（`os.IsNotExist` 直返）。
- `META_ART_DIR` 已在席位与壳子进程 env（`dispatch.go:365`），网关于
  spawn 时 `MkdirAll` 每 run 目录（`dispatch.go:352-355`）——无新凭证面。
  注记：D-24 降权迁移时该目录须保席位用户可写（现状同用户无碍）。

### 3.4 去重与优先序

- **值类哨兵**（`META_VERDICT`/`META_DELIVER`/`META_DEPLOY`）：
  文件源值优先——kind×来源二维落值，文件源一旦落值，流源同种命中
  不再覆盖；文件未落则流源值照旧生效（兼容只发 stdout 的席位）。
- **动作类哨兵**（`META_RULE`/`META_ADMIN`/`META_EXEC`）：
  流↔文件同源行**配对去重**——pending 计数：流中一条 `L` →
  `pending[L]++`；文件中见 `L` 且 `pending[L]>0` → 配对消化不处理
  （对称：文件先见则 `pending[L]--`，流中再见配对消化）。**配对键＝
  行原文整体**——被污染的流行与文件净行内容不同，不配对、各发各的
  （污染帧到网关 fail loud 留痕，净帧办成）。重试同文哨兵＝新一次
  出现，按出现序自配对，不误吃。
- `scanSentinel` 增 `fromFile bool` 形参区分两源，内部按上两则分流。
