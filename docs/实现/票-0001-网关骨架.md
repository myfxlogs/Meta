## 八栏

### 1. 目标
交付 meta 网关骨架并通过全部验收锚：SQLite 嵌入（WAL）、席位面 `SeatGateway.Attach`（RunAuth 首帧）、票相位边表机、全相位启动对账、一次性闹钟。

### 2. 为什么
自举阶段 0——一切席位/票/事件模型的地基（总设计 §13）。v1 死于心跳假活与文件/DB 相位双源；本票交付的结构（先连后领、双源互证、全相位对账）就是那两味药。

### 3. 范围内
- `go.mod`、`cmd/meta`（`meta serve` 入口；`meta secret put` 最小实现）
- `internal/db`：schema 建全九表（`ticket`/`ticket_event`/`seat`/`seat_run`/`shell`/`project`/`ceo_memory`/`budget`/`secret`）＋WAL＋`VACUUM INTO` 备份函数
- `internal/gateway`：席位面 Attach 双向流；RunAuth 验证（验不过断流）；spawn＋per-seat UDS（`run/seats/<run_id>.sock`，0600）；收养互证（收养首帧网关出示 run_token）
- 相位边表：§6.2 全边含补边四条，表驱动实现
- 启动对账：§5.3 全相位「相位×预期行动者」表
- `internal/clock`：一次性闹钟（`time.AfterFunc`，随事件重置；重启自 `ticket_event` 重算 deadline）
- `scripts/selfcheck.sh`：禁式 grep 自检（Ticker/无界循环/json 越界），退出码即判据
- 上述全部的单测

### 4. 范围外（禁线）
- 壳适配器（阶段 1）；CEO 面/前端面/外部面；命令代跑；部署闸；自动票径；预算执行闸（表可建、闸不启用）；角色卡注入；飞书
- 任何 `time.Ticker`、无界 `for { sleep }`、`encoding/json`（`adapter/` 此时尚不存在——即全仓零命中）

### 5. 设计引用
`/opt/meta` `docs/总设计.md` §3/§5/§6/§12（**施工开始时钉死 commit**）；`docs/接手者禁区.md` 全文；§15/§16 修订记录。

### 6. 验收锚（全部机器可判）
1. `go build ./... && go vet ./...` 绿
2. `go test ./... -count=1` 绿，且用例逐条覆盖：
   - a. 先连后领：spawn 后不连接＝不产生 `施工中`
   - b. 边表逐边：§6.2＋补边全边，合法边过、非法边拒（表驱动断言，漏一边＝红）
   - c. 中途死：杀席位进程→SIGCHLD＋EOF 双源→`施工中→已派`
   - d. 全相位对账：于 `设计中/施工中/审计中/部署中/待审` 各杀网关一次→重启按 §5.3 表逐相收养/回队/补 spawn
   - e. 闹钟重算：重启后 deadline 取自 `ticket_event`；已过期→立即发事件
   - f. 伪连接断流：无 token/错 token 的 Attach 被断
   - g. 收养互证：收养连接首帧出示 run_token；错误 token 席位拒续且留痕
   - h. 迁移烟测：启动后九表齐、WAL 开
3. `bash scripts/selfcheck.sh` 退出码 0
4. 备份烟测：`VACUUM INTO` 产物可被只读打开且表数一致

### 7. 验证命令
```
go build ./... && go vet ./... && go test ./... -count=1 && bash scripts/selfcheck.sh
```
