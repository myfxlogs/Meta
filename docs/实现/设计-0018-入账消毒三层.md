# 设计 0018：坏字节预防三层——DB 写面消毒 / 壳输出→note 收口 / 流出面防崩

> 需求票 `0018`（决策 67 D-45＋决策 68 业主三连问「预防了吗」）。
> 姊妹票对照：0017 修判决通道（哨兵扫描移层）；本票修**预防**——
> 让「一个坏字节瘫痪全公司」在结构上不再可能。
> 子票＝`0019`（施工）。

## 1. 需求原文与现状确诊

**需求（CEO 定向三层）**：
①网关入账消毒——一切文本（事件 note/票面 spec/任何字符串列）写入
DB 前 UTF-8 净化；②适配器禁把壳原始输出整段灌事件 note（截断＋
净化；Note 本就是预览用）；③流接口坏行防崩——marshal 前校验，
坏行跳过或替换而非 Internal 崩全流。

**实证**（决策 67 事故链复核——对术前快照 `run/meta-pre-surgery.db`
逐行字节取证）：

| 事实 | 落点/证据 |
|---|---|
| 真毒行＝2 行 ticket_event.note | 快照行 394/543：`…死因 exit=2 tail=<原始壳字节>`——`internal/gateway/dispatch.go:432` `logTail()` 把席位日志尾 300B **原文**拼进 `seat_err` 事件 note（SQLite TEXT 不验 UTF-8，毒直落库） |
| 崩点＝proto marshal 验 UTF-8 | protobuf v1.36.12 双侧强制：`proto.Marshal`/`Unmarshal` 遇非法 UTF-8 均报错（实测：marshal 返 `string field contains invalid UTF-8` **且仍回填部分 buffer**；unmarshal 全拒） |
| 崩径＝读面 marshal | `Events`/`EventsAfter`（admin.go:83/96）把毒 note 装进 `EventItem`→响应 marshal 失败→Internal；`Observe`/`CeoEvents` 同理→播报员 caster `resync` 永久 Internal→退避死循环→全路由死 |
| spec「10 张中毒」＝**误诊** | 快照内 10 个 spec blob `proto.Unmarshal` 全部成功——**它们本就健康**（BLOB 是 wire 二进制，整体按 UTF-8 扫必然「中毒」）；术后 live 库同 10 blob 全部 unmarshal 失败且各涨 8–9×`ef bf bd`——**清毒手术把好 spec 改坏了**（replace 语义对二进制列=毁 wire 框架）。数据修复走另行径（报 CEO，不入本票） |
| 毒进 proto 的非字符串道 | `NewTicket.spec`/`FillSpec.spec_md`/`MemoryPut.content` 是 `bytes` 字段——proto 不验内容；`seat.go:534` `nt.Spec, _ = proto.Marshal(ts)` **吞错**——marshal 失败时 nt.Spec=部分 wire 字节→`CreateTicketProv` 原样落库→坏 blob |
| adapter Note 已截断但不净 | `adapter.preview(s,200)` 纯字节切——不验 UTF-8，且 200B 边界可切烂多字节字符**自制**非法 UTF-8；devin 壳每行原文透传；claude/opencode 不可解析行原文透传（JSON 解析行已被 encoding/json 天然净化） |
| 同族次伤面 | `exec.go:188` `ExecResp.Tail`（`tailOfFile` 原文）跨 gRPC marshal 崩→Attach 流断；`cmd_run.tail` 同源落库；`ceo_say` 事件 `Note:string(Put.Content)` bytes→string 毒道；`board` 席位行 Stage/Note 出 `LatestStages`（毒 progress note→席位板流崩）；`Runs`/`MemoryRow` DB→proto 各串同病 |
| 席侧发件暗死 | `seat.sendPump`（seat.go:412）Send 失败静默 return——坏字节帧进队即发件泵死，无日志 |

**根因一句话**：系统对「外部字节→DB TEXT→proto string」这条链
零设防——写入端 SQLite 不验、读取端 proto 强验，毒卡在中间必炸。
修法三层都在收口点做机械净化/校验，不追上游每一个源（源无限）。

## 2. 总体方案

**净化原语**：`strings.ToValidUTF8(s, "\uFFFD")`——非法字节序列逐段
替换为 U+FFFD（�），保留可读上下文、留可见污痕（不静默丢——令#E18）。
spec BLOB 不是文本：**校验不净化**——`proto.Unmarshal` 失败即拒写
（写期 fail loud 好过读期崩流）。

**层一（入账口·正解）**：`internal/db` 新文件 `sanitize.go`——
`clean(s)`＋`cargs(args...)`（遍历参数：string→clean；[]byte/其他→
原样）。**一切 ExecContext/Exec 调用点实参一律过 cargs**（26 处，
含 Transition 的 tx.ExecContext）——单点收口覆盖全部现存与新增写径；
`CreateTicketProv`/`UpdateSpec` 的 spec 参数另过 `validSpecBlob`
（unmarshal 校验→canonical 再 marshal 落库；失败→返回错拒写）。
`PutMemory` 的 content（BLOB 存文本）按文本净化。
`inject.ParseTicketMD` 产出的十个字段逐一净化——下游 marshal 永不败，
fill_spec 不再因坏字节被拒、create_ticket 不再产残缺 blob。

**层二（壳输出→note 收口）**：`adapter.preview` 重写——先净化再按
rune 边界截断（≤n 字节不割字符）；`gateway.logTail`/`tailOfFile` 出
口净化；`seat.scanSentinel` 首行 `line` 净化（一行盖住
Rule/Verdict/Deliver/Admin/ExecReq/META_DEPLOY 全部哨兵载荷）；
`seat.sendPump` Send 错误落 stderr（暗死→有声）。`adminSentinel`
create_ticket 的 marshal 吞错改显式（err→Spec=nil 非部分字节）。

**层三（流出面·兜底）**：DB→proto 各构建点逐字段净化——
`eventItem`（Events/EventsAfter）、`ObsEvent`/`ceoEventItem`、
`RunItem`、`MemoryRow`（content 为 bytes 免）、板 `seatRow`/`ticketRow`；
`emit()` 增事件串净化（进程内事件源收口，订户全免疫——含 pending 重放）；
流发送前 `proto.Marshal` 预检（Observe/CeoEvents 逐帧、
Events/EventsAfter 逐行）——仍失败的帧/行**替换为 `bad_row` 标记帧**
（kind="bad_row"、note 带原 id——跳过留痕不静默），流自身不返 Internal。

## 3. 落点明细

### 3.1 `internal/db/sanitize.go`（新）

```go
// 入账消毒（决策67/D-45）：一切进 SQLite 的文本过 strings.ToValidUTF8。
// SQLite TEXT 不验 UTF-8、proto marshal 强验——消毒是本包写面的机械契约。
func clean(s string) string { return strings.ToValidUTF8(s, "\uFFFD") }
func cargs(a ...any) []any // string→clean；其余原样
func validSpecBlob(spec []byte) ([]byte, error) // 空→原样；Unmarshal 败→err；成→canonical marshal
```

- db 包内全部 `ExecContext`/`Exec` 实参过 `cargs(...)`（budget.go×2、
  memory.go×1、project.go×3、run.go×8、secret.go×1、shell.go×5、
  ticket.go×6——schema/ALTER/VACUUM 除外）。
- `CreateTicketProv`/`UpdateSpec`：spec 先过 `validSpecBlob`，错即返回。
- `PutMemory`：`content = []byte(clean(string(content)))`。
- db 包新增 `pbv1`+`proto` import（spec 列契约本就声明「序列化
  pbv1.TicketSpec」——校验属 schema 语义，非新耦合）。

### 3.2 `internal/inject/inject.go`

`ParseTicketMD` 构造 `TicketSpec` 时十字段逐一 `ToValidUTF8`——
源头净化：marshal 不再败（fill_spec 坏字节票可回填且留 � 痕）。

### 3.3 `internal/adapter/adapter.go`

`preview(s,n)`：`s=ToValidUTF8(TrimSpace(s))`；`len>n` 时在 ≤n 字节内
退到 rune 边界（`utf8.ValidString` 逐字节回退）再 `+"…"`。

### 3.4 `internal/seat/seat.go`

- `scanSentinel`：`line := strings.TrimSpace(strings.ToValidUTF8(string(l), "�"))`。
- `sendPump`：`stream.Send` 错→`fmt.Fprintln(os.Stderr,...)` 后再 return。
- `adminSentinel` create_ticket：`if b,err:=proto.Marshal(ts); err==nil { nt.Spec=b }`（err→nil，不再存部分字节；stderr 留痕）。

### 3.5 `internal/gateway/`

- `dispatch.go logTail`：返回前 `ToValidUTF8`。
- `exec.go tailOfFile`：返回前 `ToValidUTF8`（`ExecResp.Tail` 与
  `cmd_run.tail` 同源头净化）。
- `admin.go eventItem`：Kind/FromPhase/ToPhase/Actor/Note/TicketId/
  Role/Provenance 逐字段净化。
- `admin.go Events`/`EventsAfter`：逐 item `proto.Marshal` 预检，
  败→替换 `EventItem{Id,Kind:"bad_row",Note:"事件行序列化失败（已隔离）"}`。
- `admin.go Runs`：RunItem 字符串字段净化。
- `admin.go Observe`：`ObsEvent` 构建净化＋`proto.Marshal` 预检，
  败→`ObsEvent{Kind:"bad_row",Note:...}` 顶替照发。
- `gateway.go emit`：入口 `e` 各字符串字段净化（进程内事件源单收口）。
- `ceo.go ceoEventItem`：字段净化；`CeoEvents` 循环 Send 前预检
  （pending 重放同径）。`CeoMemory` get 的 `MemoryRow` 字段净化。
- `internal/board/board.go`：`seatRow`/`ticketRow` 的 DB 源字段净化
  （Stage/Note/Title/Role/Shell/RunId）。

### 3.6 契约/文档面（无）

净化是机器行为，席位契约零变——不改角色卡/注入模板/路由表。

## 4. 边界外

- **历史 10 个被手术改坏的 spec blob**（0009–0017、req-9ce5）——
  数据修复＝从 `run/meta-pre-surgery.db` 快照复原，属事故收尾另行径
  （禁区#6 须业主/CEO 例外令），非本票码面。
- 存量 ticket_event 毒行已于术晨清毕；残余毒层三兜底为「替换标记帧」。
- 席位日志/exec-resp.log/sentinel.log 是文件不是 DB——原文照存
  （取证要原物；净化只管进库与进 proto 的文本）。
- `ad.Classify` 输入 tail、`relayExecResp` 落盘行——非 proto/非 DB，不动。
- devin CLI/ACP、shell stderr 直透席位日志——厂商面不归。

## 5. 风险与回退

| 险 | 对策 |
|---|---|
| spec 校验拒写影响存量合法写径 | 合法 marshal 产物必过 unmarshal——零破坏；非法 blob 本就该拒（fail loud） |
| canonical re-marshal 改写 blob | 语义等价；读取径全走 Unmarshal |
| cargs 漏包新写径 | 锚＝`grep -c cargs( internal/db` 对账所有 ExecContext 点 |
| U+FFFD 进哨兵 ref | 哨兵 ref 本就 ASCII；坏字节行的哨兵已废，净化保住可解析部分——语义不变 |
| 回退 | 全改动收 sanitize.go＋各净化调用行；revert 即旧行为 |
