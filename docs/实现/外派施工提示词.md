## T1 部署通道手术（状态：待发｜吸收 0037-p2-p1、0040、0034-p1-p1、0038-p1-p1）

**病根**：`config/gateway.textproto` 的 `integrate_cmd`（36 行）只会快进合并
（`merge --ff-only`），分支与 master 一分叉即全线红；且不先验分支存在，报裸
pathspec 错。当日 6 票约 20 次部署全死于此。

**改法**：
1. `integrate_cmd` 重写三段（单条 shell、沿用 `$META_EXEC_REF`、仓库 /opt/meta）：
   ① `git rev-parse --verify "$META_EXEC_REF" || exit 92`（分支不存在=专码 92）
   ② `git merge-base --is-ancestor "$META_EXEC_REF" HEAD && exit 0`（已合入，幂等）
   ③ `git merge --no-ff "$META_EXEC_REF"`（真合；真冲突退出非零，回滚语义如旧）
2. `internal/gateway/exec.go`（约 171 行 merge_conflict 判读处）：按退出码区分
   「分支丢失(92)」与「真冲突」，事件 note 前缀 `REF_LOST:`/`CONFLICT:`；
   两类事件照发不静默。
3. 单测三条新路径（已合入幂等／分叉可合／分支丢失红）＋既有快进路径不回归。

**禁区**：不动 check/deploy/probe/rollback 四步；不改路由表语义。

## T2 CEO 决策通道（状态：待发｜D-61＋D-64）

**病根**：`meta memory --put` 要 `META_RUN_TOKEN`（席位专属）→ 终端 CEO 决策
只能落 commit 信息（决策账 DB 无终端写径）；`meta rule` 裁决成功后不写
ceo_memory（首航实证零写警告×2）。

**改法**：
1. 终端受控写径：`meta memory --put` 增终端形态鉴权——核验
   `run/ceo-present.json` 的 pid 存活（在岗锁即凭据），过则放行写 DB；
   不过=拒。不开无鉴权径。
2. `meta rule`（void/budget_raise/redirect）每笔成功裁决自动写 ceo_memory 行：
   决策+理由+provenance=terminal+署名。
3. 单测：在岗锁活→写成功；锁缺/ pid 死→拒；rule 落账断言。

**禁区**：不动席位 token 径；ceo_memory 表结构不动（只写入径）。
