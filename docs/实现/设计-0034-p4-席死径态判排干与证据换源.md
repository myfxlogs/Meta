# 设计-0034-p4：部署态判双径失守三补——死席哨兵排干＋席死径挂态判＋证据换源

> 需求票 `0034-p4`（巡检自立案 adjunct）→ CTO-A 设计 → 子票 `0044` 施工。
> 钦定轨（§1.4）：设计档 commit → 本票八栏回填 → 子票立＋派 → Deliver。
> 结论先行：票面三缺逐条坐实（§0）。核心钦定＝**部署中席死判前两级判：
> 先排干死席 sentinel.log 末条 META_DEPLOY 哨兵，无终哨兵再查
> deployStateOK（证据换源后 restart 径可真），双路俱无据才
> deploy_failed**——D-2「无已装证据仍翻负」对真败径语义不退。

## 1. 总机制（一图）

```
部署席（scope 或连坐死，不定）          sentinel.log（壳双发件，落盘幸存）
   │ 部署四步物理绿                        META_EXEC:*  +  META_DEPLOY:done
   │ upgrade 已装 → restart 杀 cgroup           ▲
   ▼                                           │ 死判时刻整读（末条 META_DEPLOY 胜）
席死双径                                网关侧排干（本票新增件）
 ① attach.go SIGCHLD+EOF 分支  ──┐    done→deploy_done / failed→deploy_failed
 ② reconcileActor 死席分支     ──┤    无终哨兵 → deployStateOK 态判
   （同排干同判，机制一处两用）    │        已装证据 ∧ stamp 等 ∧ Probe 绿
                                ▼        → deploy_done＋双锁释放
                        双路俱无据 → deploy_failed（D-2 语义不退）
```

## 2. 机制一：死席 sentinel.log 排干（网关侧末泵，两处挂点）

- **文件**：`filepath.Join(g.cfg.RunDir, "artifacts", st.run.RunID,
  "sentinel.log")`——钦定落点（ceo.go:236、dispatch.go:463 同式），
  从 run 推径，无需 DB 新字段。reconcile 径同式（run.ArtifactDir 不入
  库，RunID 即目录名）。
- **语义**：席死＝文件终态，整文件一次读（小文件，无 offset 续读问题），
  取**末条** `META_DEPLOY:` 行：
  - `META_DEPLOY:done` → `transition(完成, EdgeDeployDone)` +
    `emit(deploy_ok)` + `releaseProjectLocks(integrate, deploy)` +
    `cancelAlarm` → return（与 reconcile.go:213-219 既有序同构）
  - `META_DEPLOY:failed` → 照旧 deploy_failed——note 改记「哨兵在盘：
    failed」，证据留痕不蒸发
  - 无 `META_DEPLOY:` 行 → 落机制三（deployStateOK）
- `META_DELIVER:` 行在场**不翻边**（部署票终哨兵＝META_DEPLOY，DELIVER
  只是载体）——可在 note 留痕「deliver 在盘」，不消费成边。
- **挂点两处**（同一排干函数）：
  ① `attach.go` 席死分支 `case db.PhaseDeploying:`——钦定主挂点，
  transition 前替换现「直翻」语义；
  ② `reconcileActor` 的 PhaseDeploying 死席分支（reconcile.go:206-208
  前置）——boot 对账径同病同源：restart 双杀时席死对账先于 Serve，
  盘上的 done 是唯一不依赖 socket 的幸存证据，同机制排干即收口，
  不收则「签名绝迹」锚在 boot 径失守。ticket 票面点名 attach 挂点，
  对账挂点为同机制必要延展，范围注明非扩票。
- **事件驱动单发**：死判时刻一次读，禁扫描轮/定时器（红线#1 同构）。

## 3. 机制二：deployStateOK 证据换源（跨 restart 存活证）

判据改**联合三要件**，全真才判部署实成：

1. **已装证据**（二取一，跨 restart 存活源）：
   - a. `cmd_run` 末次 deploy 步 `exit=0` 行在——非 restart 径仍落库
     （幂等短路退 0 / RestartCmd="" 径），留作旁证通道不拆；
   - b. **最新** `run/exec/<tid>-deploy-*.log` 含
     「upgrade: 已装 <new> → <install>」行（upgrade.go:62 钦定行，
     死进程日志文件按路径存活）——行内目标段给 install 位（绝对径
     自含）。glob 取最新份（名带 UnixNano，字典序即时间序）。
   - 两源俱无 → 要件假 → false（**无已装行仍翻负**，票面锚4）。
2. **stamp 比对**：`<install> version` 第二段 == 期望 stamp。
   期望源**钦定优先序**（语义＝「装着的＝这次该装的」）：
   - 首选：已装行锚定的 NewBin 文件 `version` 第二段——同文件对
     互证，免 git、免 master 漂移（`bin/meta.new` 与 `bin/meta` 在
     0034 实景同戳互证）。NewBin 相对径相对项目 `repo_url` 解析；
   - 次选：项目 `repo_url` 内 `git log -1 --format=%h -- 码面
     pathspec`（pathspec 与 meta-deploy.sh:20 同源复写）+
     `-deploy` 后缀——「master 现状」钦定语义；
   - 施工可在两源间择主，**比对语义不动**：装戳＝期戳才过。
3. **socket Probe 保留**：`upgrade.Probe(g.cfg.SocketPath, 2s)`——
   部署效果独立证据位。attach 径（Serve 已起）恒可探；boot 对账径
   无哨兵时 Probe 红→判负——保守方向正确（无哨兵无已装证本就该负；
   有哨兵者已被机制一排干收走，Probe 不挡）。

## 4. 机制三：席死径挂态判（attach 分支两级判全序）

`attach.go` `case db.PhaseDeploying:` 现直翻逻辑替换为：

```
drain := 排干(artifacts/<runid>/sentinel.log)
switch drain:
  done   → deploy_done 边（机制一序）→ return
  failed → deploy_failed（note 记哨兵在盘）→ return
无终哨兵:
  deployStateOK(tid) == true
    → deploy_done 边 + emit deploy_ok + 放 integrate/deploy 双锁 → return
    → false → 照旧 deploy_failed（现 note 文案不变，先核回滚态）
```

- 锁释放与事件面镜像 reconcile.go:213-219 既有序——deploy_ok 语义
  两径同形，不造第二种完成式。
- 非部署票/他相位席死径一律不动——排干只挂 PhaseDeploying 判定链，
  爆炸半径最小。

## 5. 时序三径

- **绿径（0034 实景回放）**：deploy 四步绿→「已装」行入 exec 日志→
  restart 灭席灭网关→席死判（attach 或对账）→排干得 done→
  deploy_done→票完成。cmd_run 无行、stdout 缓冲丢不丢都收口。
- **哨兵失但实装径**：done 未落盘（泵未及）→deployStateOK：exec
  日志已装行在＋NewBin/install 同戳＋Probe 绿→deploy_done。态判
  不再寄生席存活与 cmd_run 落库。
- **真败径（D-2 保）**：deploy 步真败/未装→无已装行/stamp 不符/
  Probe 红→deploy_failed，note 照旧「先核回滚态」。翻负方向不放宽。

## 6. 记档（残险与判词）

- **boot 对账 Probe 结构性红**：New() 内 reconcile 先于 Serve
  （gateway.go:347 vs 361），socket 已绑未接客→Probe 恒超时。机制一
  排干挂对账径后，有哨兵者不再经 Probe；无哨兵＋实装场景在 boot
  判负系钦定保守（debounce/手动 reconcile 复跑时 Probe 可绿，
  二次对账可翻回——**注意**：deploy_failed 已翻负的票不回部署中，
  复跑不再判，属已知残险，归 CEO 事件裁，不为此加扫描窗）。
- **master 漂移窗**：装戳比对若取 code-head 现算源，部署后判前有码
  提交合入→期戳漂移→保守判负（方向安全）；首选 NewBin 文件对证
  免疫此窗，钦定优先序已给。
- **NewBin 被后续部署覆写**：部署锁串行（B1）下，本票判定时无并行
  部署改 pair；他票后续部署覆写 meta.new 时本票已终态——窗口
  概率≈0，错配方向保守。
- **幂等短路**：cur==stamp → meta-deploy.sh 退 0 不 restart——席活
  cmd_run 落库，老径收口原样不动。
- **排干单源性**：sentinel.log 是壳侧双发义务件——壳不写文件则排干
  空，落态判兜底；两径俱无→保守负。不因此放宽判据。
