## 2. 0021 设计：D-44 四合修＋D-35

### 2.1 表外默认通知（E13 铁律②法码顶牛的正解）

**病**：铁律②钦定「表外事件只通知不处置」，实现成**静默丢弃**（0014 的
spawn_needed(CTI) 两声喊被吞＝决策 64 确诊）。现测试锚「表外零调用」把错
的写成了对的——**锚本身要改判**。

**修法**：`RouteTable` 增 `default_notify` 块（proto 新字段→protoc regen）：

```proto
message RouteTable { repeated Route routes = 1; DefaultNotifyRule default_notify = 2; }
message DefaultNotifyRule {
  repeated string kinds = 1; // 无路由匹配且 kind 命中→通知（不处置）
  string template = 2;       // 空＝缺省模板【Meta】{{role}}:{{action}}[{{ticket_id}}]
}
```

caster `process()`：行匹配循环记 `matched`；零匹配且 kind∈default_notify.kinds
→execNotify。**降噪**：单次 resync 批内 (kind,ticket_id) 只报首枚（回放风
暴/积压对账不致刷屏；跨批新事件照报＝每个新病仍疼，同批重放不重复疼）。
非种子 kind（progress/usage/seat_up/adopted 等正常流水）照旧零调用——
噪音面不扩。

种子集（textproto 落值，改表走票）——异常/阻塞/死类全收：
`spawn_needed, spawn_failed, spawn_dup, spawnq_full,
inject_failed, seat_err, adjunct_dead, adjunct_yield, adopt_failed,
budget_reset_failed, budget_stop, exec_denied, shell_dead, shell_recovered,
ceo_gap, ceo_last_resort, yield, req_pending, design_dead, void, budget_warn`
（**spawn_blocked 钦定不收**——决策 75：队列内务不通知防刷屏，终态已有
shells_exhausted 通知；seat_dead 不收：正常交付退席同打此 kind，收则刷屏）。

### 2.3 spawn_needed(CTO) 分线：CTO-A 设计支 / CTO-B 部署支

**病**：现单行 `note_contains: "CTO"` 派 `cto-deploy.md`——已立票（PhaseCreated，
该起 CTO-A 设计席）补发也吃部署模板＝设计期票误用部署模板的隐患（CEO 点名）。

**修法**：发射端 note 加支线标记（§14 半结构契约同步改表），消费端拆两行：

| 发射点 | 相位语义 | 新 note |

| reconcile.go 已立票补发 | 设计支 | `对账补发: CTO-A` |
| reconcile.go 待部署票补发 | 部署支 | `对账补发: CTO-B` |

| attach.go 部署席 claim 前死锁释补发 | 部署支 | `锁释补发: CTO-B` |

| ceo.go releaseDesignLock 同项目已立 | 设计支 | `对账补发: CTO-A（设计锁释放）` |

路由表两行：

```textproto
routes { kind:"spawn_needed" note_contains:"CTO-A"
  actions { dispatch { role:"CTO" work_dir:"/opt/meta" prompt_template:"caster/cto-design.md" } } }
routes { kind:"spawn_needed" note_contains:"CTO-B"
```

## 3. 0022 设计：D-46 审计重派壳偏置

**病**：审计席死→重派，同壳连败照试（D-42 席位级死因不进 failSet 不迁健康，
循环烧壳——0016×8 实证，opencode 日限被打穿）。

**修法**（`dispatchOnce` 内，role=="审计" 才生效——机械判不越权）：

1. 取 `RunsForTicket(ticketID)` 中 role=="审计" 非 adjunct 的 run，新→旧扫：
   同壳且 `Dead && ExitCode != 0` 连败计数（遇他壳或 ExitCode==0 即断）。
2. 连败 ≥N（默认 2，`gateway.textproto` 新配置 `audit_shell_skip_streak`，
   proto 字段→regen）→该壳从本轮 attempts 剔除＋emit `audit_shell_skip`
   事件（note=壳名+连败数——落 0021 的 default_notify 种子自然通知）。
3. 剔除后 attempts 空→照旧 `shellsExhausted`（通知→CEO 裁）。

**边界**：只偏置审计重派；施工/CTO 不动；健康迁移机制不碰；席位级死因仍不
记壳账（D-40 原则不动——偏置是「本轮跳过」，不是「标壳坏」）。

**锚**：造 run 行（helper_test 开库惯例）——同壳 2 连败→候选无该壳；1 败照
试；中间夹 ExitCode==0 成功行→断计；role=施工不生效；对抗锚：删连败比较
行→死壳被重试→红。

## 4. 0023 设计：前端板深验脚本

**病**：决策 71 定板「半活」（监听与路由在、页面与帧未验）。

**修法**：`scripts/board-verify.sh` 一把梭 scratch 验收（自含实弹，不依赖
生产 token）：

```bash
TMP=$(mktemp -d)
meta secret put --db $TMP/meta.db --key $TMP/vault.key secret.board.token <<< tok
meta serve --db $TMP/meta.db --socket $TMP/meta.sock --rundir $TMP/run \
     --board-listen 127.0.0.1:$PORT &            # PORT＝脚本内取空闲端口
meta ticket new --socket $TMP/meta.sock --id va --title 验A   # 先于接入 → FULL 帧含 va
meta board --connect http://127.0.0.1:$PORT --token tok --n 3 > $TMP/frames &
meta ticket new ... --id vb && meta rule --action void --ticket vb --confirm  # →TICKET_UPSERT
meta rule --action void --ticket va --confirm                                  # →TICKET_UPSERT
```

断言：client rc=0 且 frames 含 `FULL ` 行 ≥1＋`TICKET_UPSERT` 行 ≥2
（FULL＋两 void 变化帧＝3 帧达标）；有界等待（≤15s，超时即红——bash 有界
等待非系统周期任务）。`--live` 旗：给 `META_BOARD_TOKEN` 则对
`http://127.0.0.1:9712` 同径打 3 帧（生产已验径）。

**锚**：`bash scripts/board-verify.sh` rc=0 且帧行达标；反锚——对未挂端口跑
（`--connect 127.0.0.1:1` 类死地址）rc≠0。
