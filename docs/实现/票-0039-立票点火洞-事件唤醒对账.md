# 票 0039：立票点火洞收口——票事件去抖唤醒对账闹钟

> 立票：CEO（终端形态）·决策 91·2026-11-02。业主令：「不是手动点火，是找出
> 为什么没有点火」——根因：`created` 事件无路由（全表唯一），裸立票径无点火
> 载体，对账只在启动时跑。0037/0038 实证滞留。根修＝事件唤醒对账。

### 1. 目标
票事件驱动的去抖对账闹钟：任意相位变迁类 `ticket_event` 追加（至少
created/design_start/dispatch/claim/yield/reject/deploy_* 族）重置一次性
闹钟（去抖窗默认 30 秒、textproto 可配），闹钟醒→跑既有 `g.reconcile`
（幂等径不改）。裸立票后无需人工、无需重启，必进流程。

### 2. 为什么
E13/E18「看见即路由」在 created 上是空话；三条立票径两条自带点火（需求径
CEO 泵、巡检自领），裸立票没有。对账闹钟一处修全局免疫：派发重试耗尽、
锁释补发漏发、任何未来事件的滞留形态，醒来对账即自愈——对账本就是全相位
「相位×预期行动者」判别表（patrol 票不会误派 CTO）。R2 合规：被叫醒合法
（事件重置一次性闹钟），零周期、零快照表。

### 3. 范围
- `internal/gateway`：一次性闹钟（patrol alarm 同形制——`time.AfterFunc`
  重置式）；订票事件追加（AppendEvent 落账成功后）→ 重置；醒→
  `g.reconcile(ctx)`（goroutine 内，防阻塞事件径）。
- 去抖窗常量进 `config/gateway.textproto`（如 `reconcile_debounce_s`）。
- 单测：①立票→闹钟必设→醒后对账补发必发（相位离已立）；②窗内多次事件
  只醒一次；③闹钟醒时无滞留→对账空转无害。

### 4. 禁区
- 周期轮询/cron/固定间隔重扫/快照表（R2 红线——测试须断言无 `time.Tick*`）。
- `reconcile.go` 对账逻辑本体（只加触发，不改判别）。
- caster 路由表加 `created` 路由（会把 CTO 误派到 patrol-* 票——经验库
  2026-11-02-立票不点火 规约 2）。
- 历史滞留批量回填；通知面新增。

### 6. 对抗锚
- 裸立票（`meta ticket new`）后 ≤去抖窗＋5 秒：`spawn_needed` 必发、相位
  必离已立（全链无人工无重启）。
- 连续立两票（窗内）：对账只跑一次（去抖合并）。
- `patrol-*` 裸立票：醒来对账后派的是巡检不是 CTO。
- 代码锚：新路径零 ticker/零周期 goroutine。
