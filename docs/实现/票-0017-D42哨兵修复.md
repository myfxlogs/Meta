# 票 0017：D-42 判决哨兵修复——扫描移层＋sentinel.log 双发兜底

### 1. 目标

修复 D-42（决策 60/62/63）：席位外壳哨兵扫描从原始 stdout 行移到
**适配器解析后文本流**；新增 `$META_ART_DIR/sentinel.log` 文件兜底
通道（事件驱动增量读）；契约改「哨兵双发」并同步全部契约文本面；
补单元＋端到端测试。设计全案＝`docs/实现/设计-0016-D42哨兵扫描移层.md`。

### 2. 为什么

- 决策 60/62 实证：四班＋六班审计全 exit=0 无捕获判决——claude/opencode
  的 JSONL 壳把哨兵包进字符串，`seat.go:264` 行首扫原始行永不命中，
  判决全丢→audit_dead 重派循环→全壳耗尽×N。
- devin 同族缺陷：`run/logs/ca93f994*.log` 实录渲染层吃内嵌换行，
  `META_ADMIN:fill_spec|<path>` 载荷被粘文污染（file name too long）——
  行首锚定的 substring 无解，须第二信道。
- 解锁面：审计回偏 claude 复异壳（决策 63 晨课）；判决/交付回流
  从此壳无关。

## 附

- **本票施工自身的哨兵风险**（如实告知）：本席运行的 seat 二进制是
  修复前版本——devin 壳上 `META_DELIVER`/admin 哨兵仍可能被行合并
  吞掉。绕行径（req-9ce5 实证）：若哨兵发出未见效应（无 admin_resp /
  未捕获），直写独占行到 devin 进程 fd 1——
  `echo 'META_DELIVER:<ref>' > /proc/$(pgrep -f 'devin -p' | head -1)/fd/1`。
- 依赖：无（`META_ART_DIR` env/目录机制已在）。部署换装归既有部署径。
- 优先级：最高（审计回偏 claude 解锁件）。
