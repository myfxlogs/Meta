## 八栏

### 1. 目标

`feishu_card` 表（`ticket_id PK,message_id,chat_id,updated_at`）＋网关内
第三事件消费者：订 g.events，**一切非 usage 票事件→重渲染全卡**（无 diff
计算）→**内容哈希变才 PATCH**（天然合并刷帧，进度连发不连发 PATCH）；
卡面＝票号/标题/相位/当前席（role·shell·stage）/进度 note/用量/驳回数/
时间；创建懒化（首见非终态票事件→create 发卡→落 message_id 行）；
启动对账（扫非终态票无卡→补建，一次性 R2 合法）；创建失败→记事件不阻塞
（文本兜底在）。

### 2. 为什么

E14/决策 41 钦定「前端席位板进手机」：每票一张卡全程刷新（接单/在干/完工/
审计/判决/部署/完成）；决策 38 同判推演——卡片状态要 DB 持久（caster 无写径）、
更新要合并刷帧（无哈希闸进度帧打爆 PATCH 配额），故消费者驻网关进程。

### 3. 范围内

- **`internal/db`**：`feishu_card` 新表＋CRUD。
- **`internal/feishu/card.go`**：渲染器（票+相位+席+stage+用量+驳回数→
  卡片 JSON——JSON 止于本适配层）；事件订阅循环（非 usage 事件→重渲→
  hash 变→lark update/create）；启动对账补卡；创建失败记事件不阻塞。
- 文本通知不删（卡是席位板进手机，文本是兜底与历史流）。
- 单测＋对抗锚。

### 4. 范围外（禁线）

- 文本通知径；卡面美术；非 meta 项目卡；diff 计算优化（全卡重渲已钦定）。
- 定时合并窗（R2——超频→调用错→下事件再试，懒修）。

### 6. 验收锚（全部机器可判）

1. `go build ./... && go vet ./...` 绿；`go test -count=1 ./...` 绿（原文 tee）；
   `bash scripts/selfcheck.sh` 绿。
2. **创建懒化**：伪 sender 下事件序列→create 一次＋update N 次且同
   message_id。
3. **哈希闸**：同内容二帧→零 PATCH；usage 行→零调用。
4. **启动对账**：伪库两票非终态无卡→两 create。
5. **不阻塞**：create 失败→事件行＋主流程不炸。
6. **对抗性锚（≥2）**：a. message_id 复用行删→每事件新卡锚红；
   b. 哈希变判断行翻→内容不变也 PATCH 锚红。
