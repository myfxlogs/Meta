# 票 34：巡检链路两缺——过滤壳死因分类＋patrol-* 正派发兜底提示

> 票面（施工输入）；经 `META_ADMIN:create_ticket` 入 DB 后派发。
> 设计全案＝`docs/实现/设计-patrol-1793586336-p1-巡检链路两缺.md`。

### 1. 目标

修巡检链路两缺（11-02 实证）：

- **过滤壳死因分类**：`cheapFilter` 失败时 `filter_degraded` note 裸
  `signal: killed`/`输出不可判` 无分类——改带分类词（超时/限额打穿/
  起壳败/退码非零/输出不可判）＋净化证据尾。
- **patrol-* 正派发兜底**：`dispatchOnce` 注入机缺（InjectRoot 空）或
  组装败时，patrol-* 票合成最简值班提示兜底，不再裸撞 D-40 空提示闸。

### 2. 为什么

- 10:25:36 `filter_degraded signal: killed`（事件 2638）＝90s 超时被杀，
  与限额退壳/OOM/起壳败不可分——下次坏照样瞎。
- 同刻 `patrol-1793586336` 值班票 `spawn_blocked 空提示拒起 role=巡检`×2
  （事件 2642/2643）：unit 10:27:24 前无 `--inject-root`，patrol-* 自动
  派发不带 PromptFile → 空提示撞闸。巡检是「机器坏时仍能报信」的兜底径，
  不能依赖被它监视的设施。
- 症状修已在位（300s 超时 `91cc202`、JSONL 兜底+恒巡检 `5b1a21c`、注入机
  上线）；本票补死因分类＋兜底＋回归锚三根债。

### 6. 验收锚（全部机器可判）

1. `go build ./... && go vet ./...` 绿；`gofmt -l internal/` 零命中；
   `go test -count=1 ./internal/gateway/...` 绿。
2. `TestFilter_ClassifyExit` 表驱六 fixture 全绿：超时 ctx→「超时」；
   限额 stderr→「限额」；限额 JSONL stdout→「限额」；非 ExitError→
   「起壳败」；无特征 ExitError→「退码非零」；`quotaLike` 正反例。
3. `TestFilter_QuotaUnjudgeable`：无 KEEP/DROP 且含限额特征的输出→
   错误含「限额」字样非裸「输出不可判」。
4. `TestT34_PatrolDutyFallback`：`InjectRoot==""` fixture 下
   patrol_tick→立票→派发→`shells_exhausted`（抵壳路由，非
   `spawn_blocked 空提示`）且兜底件非空含票ID＋`META_DELIVER`；
   改后 `TestT30_PatrolRoute` 绿。
5. 对抗锚（删/翻必红）：`classifyFilterExit` 超时分支——删→锚2 超时
   fixture 红；`quotaLike` 判定行——翻→锚3 红；dispatchOnce patrol
   兜底支——删→锚4 回 `spawn_blocked` 红。
6. 手验：`meta inject --kind patrol_tick` 后 `meta events`——过滤壳
   真判定（KEEP/DROP 生效），或 `filter_degraded` note 含分类词
   （超时/限额/起壳败/退码非零/输出不可判）非裸 `signal: killed`。
