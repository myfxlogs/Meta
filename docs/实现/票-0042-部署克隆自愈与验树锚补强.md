# 票 0042：部署克隆自愈径＋验树疤形锚补强（0034-p2 残留收口）

> 设计票 0034-p2 的执行子票。设计档：
> `docs/实现/设计-0034-p2-部署克隆自愈与验树锚补强.md`。

### 1. 目标

T13 已修「check 验树脱靶＋克隆钉死」主病灶（f22a575 已并在跑）；
本票收口三件残留——① `ensureDeployClone` 残缺克隆自愈径；
② 生产疤形 fixture 测试补缺；③ `docs/总设计.md:281` cwd 语义订正。

### 2. 为什么

- **残目录永堵**：克隆中途死（SIGKILL/OOM/换装重启）或残置→
  `run/deploy/<tid>` 在非 git/残损态→现码同步径 fetch 步必败→
  每部署同点复败，唯人手删目录可解——与 0034-p2 立案的「结构性
  堵死」同族，机制内自愈才对。
- **疤形未进测试**：生产实态 detached-HEAD 克隆（run/deploy/0034）
  与 checkout-ref 旧世界克隆两种形状均无 fixture 锁，回归可溜。
- **真源与码漂移**：总设计 281 行仍写「交付 commit 干净 worktree」
  旧语义，读者会按旧世界理解部署验树对象。

### 3. 范围内

- `internal/gateway/exec.go` `ensureDeployClone`：同步径 git 步败、
  或 dir 位存在而非目录 → `os.RemoveAll(dir)`＋全量重克隆**一次**；
  再败照原 fail loud 原文返回。`repoURL==""` 径不动。
- 同函数注释补 repo_url 前提一句（repo_url=本地径语义＝并后本地
  主线顶；远端 URL 项目拉远端顶——现唯一登记项目 meta）。
- 新增 `internal/gateway/t0042_test.go`：三 fixture（残缺目录自愈／
  detached-HEAD 旧克隆同步／checkout-ref 旧克隆同步），fixture 手法
  沿用 t1Repo/t1Git/dispatchCfg 母形。
- `docs/总设计.md` §10 命令代跑行（:281）cwd 语义订正为 T13 现语义：
  cwd＝`run/deploy/<tid>` 克隆每步同步到 `<default_branch>` 顶
  （验树对象＝并后主线），交付 ref 仅经 META_EXEC_REF 作 integrate
  输入。

### 4. 范围外（禁线）

- 不动 T13 钦定同步语义（fetch+checkout+reset --hard FETCH_HEAD+
  clean -fdq）、笼挂参数、三锁、配方、部署四步序、T12 守卫语义。
- **禁手删 `run/deploy/` 任何现存克隆**（机制径自愈是测试对象本身）；
  禁手并 master；照例 worktree 支交付，禁占主仓直改。
- 自愈限**一次**重克隆——禁循环重试/静默降级；`repoURL==""` 径
  不碰；不自扩立他项。

### 6. 验收锚（全部机器可判）

1. `go test -count=1 ./internal/gateway/ -run 'TestT0042'` 绿——三
   fixture 全过：残缺目录（非 git/半克隆）→自愈成 git 仓且
   HEAD＝主线顶；detached-HEAD 克隆→HEAD＝主线顶且挂在本地
   `<branch>` 上；checkout-ref 克隆→HEAD＝主线顶而非 ref。
2. **对抗锚**：回删自愈径（RemoveAll＋重克隆段）→残缺目录
   fixture 必红；回删 T13 同步段→`TestT13_CloneSync` 必红。
3. `grep -n "交付 commit 干净 worktree" docs/总设计.md` 无命中，
   且 §10 段内检出 `run/deploy`＋主线语义新文案。
4. 自愈再败（第二次 clone 也败）仍非零退＋原文 tail 返回——
   fail-loud 断言在测试内。
5. `export PATH=/usr/local/go/bin:$PATH && go build ./... && go vet
   ./... && go test -count=1 ./...` 全绿（含 `TestT13_CloneSync`、
   `TestDeploy_LegacyDenied` 保绿）。
