## 八栏

### 1. 目标

`internal/feishu` 新包——飞书全 I/O 归网关一进程三件（禁区#16）：
larkws WS 入站（`im.message.receive_v1`→open_id==owner 白名单→
`feishu_inbound` 事件（ticket_id 空串行）→CEO 泵馈口；非业主→礼貌回绝
出站模板）；入站机械回执「收到，这就去办」（不等 CEO——对话感第一拍）；
`ceo_say` 事件消费→文本发 owner chat；`secret.feishu.app` 行网关以
vault.key 自解（不走 Secret RPC），按 `FeishuApp` proto 解，解析失败→
`feishu_cred_bad` 事件＋通道不启（fail loud）；WS 重连＝SDK 内建＋外层
指数退避（传输层 R2 边界合法）。顺手清 D-35（caster 重连循环
ClientConn 显式 Close）。

### 2. 为什么

E12/§8 通道归网关：入站不依赖人工在终端是「飞书发一句需求」的入口；
出站走通道而非脚本（职责不混——播报员仍管单向机械通知，feishu-notify.sh
继续服役）；凭证解析失败宁可通道不启也要 fail loud（带病通道比没通道毒）。

### 3. 范围内

- **`internal/feishu`**：WS client（larksuite oapi-sdk-go/v3，钉 ≥7 天前
  发布版本，总设计 §3.1 钦定件，借 `/opt/meta-archive/mbusd/cmd/
  feishu-ingress/main.go` 白名单/退避形不借码）；白名单闸（owner open_id
  等值比较）；机械回执；say 消费→发 owner chat；reconnect 指数退避；
  凭证解析（`FeishuApp` proto blob 先试，KEY=VALUE 行格式兜底双试）；
  入站→`g.ceoEvent` 内部馈口（0011 泵接口）；出站失败仅记日志+事件不炸环。
- **proto**：`FeishuApp`/`SandboxSpec` 无关本票——`FeishuApp` 消息＋
  `feishu_inbound`/`ceo_say`/`feishu_cred_bad`/`ceo_last_resort` 事件 kind
  消费接点（事件行即 ticket_event，无需新 proto kind 面——按现状 emit 约定）。
- **`internal/db`**：`secret.feishu.app` 格式核验＋必要则 `meta secret put`
  重打包步骤（票面注明为部署步）。
- **`config/caster.textproto`**：`feishu_inbound`/`ceo_say`/`ceo_gap` 等知行
  （通知面，dispatch CEO 行不写——CeoGateway 消费径按 0011 落地接线）。
- **顺手债 D-35**：`internal/caster` 重连循环 `ClientConn.Close()`。
- 单测＋对抗锚。

### 6. 验收锚（全部机器可判）

1. `go build ./... && go vet ./...` 绿；`go test -count=1 ./...` 绿（原文 tee）；
   `bash scripts/selfcheck.sh` 绿。
2. **入站**：handler 伪事件单测——owner 消息→`feishu_inbound` 行＋泵馈达；
   非 owner→回执函数捕拒答。
3. **凭证**：解析双格式 fixture（proto blob／KEY=VALUE）；坏凭证→
   `feishu_cred_bad` 事件＋通道不启。
4. **出站**：say 消费伪 sender 捕文本。
5. **重连**：WS Start 返回→退避重起有界断言（上界＋次数界，非无界）。
6. **D-35**：caster 重连循环 Close 调用断言（伪 conn 计次数）。
7. **对抗性锚（≥2）**：a. 白名单等值比较行翻→非业主也进泵锚红；
   b. `feishu_cred_bad` 早退删→坏凭证通道照启锚红。
