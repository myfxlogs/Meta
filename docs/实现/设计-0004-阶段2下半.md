## 0. 一句话

播报员从「bash 通知脚本」升级为 **`meta caster` 子命令**：以 `ticket_event` 为唯一真源做
**水位游标回读**（断线补报即同一码径），按 **textproto 路由表**把事件机械映射到
「通知／调网关 Dispatch」两类动作；为让 `stall_suspect→CTO 裁决席` 真闭环，网关引入
**adjunct 席**（不占相位、不动闹钟权属的辅助实例）与 **`SeatMsg.rule` 裁决回流帧**。
决策 40 补进**审计派发径**：与 adjunct 相反，审计席是**相位步行席**——`待审` 可派、
claim 走 `audit_start`、判决 Deliver 翻 `audit_pass`/`reject`，审计派发与判决写径自此有码位。

## 1. 关键取舍（先给理由）

### 1.1 匹配引擎放播报员侧，不进网关

- **决策 38 已裁**：播报员独立件四维里三维优于内置（核心纯净/迭代自由/经得起网关自升级——
  meta 升级频繁期通知不该跟着弹跳）。本设计是它的码件落地：引擎是网关的**客户端**，
  不是它的一块内脏。网关无任何路由概念。
- 现 `events-caster.sh` 无法承载：bash 解不了 textproto、说不了 gRPC、做不了水位原子写。
  故新引擎＝**`meta caster` 子命令**（单二进制内，`AdminGateway` over unix socket 客户端）。
  脚本退化为薄壳 `exec`，生产单元命令行零改动（范围内不动 systemd 单元，见 §10）。
- 反案备查（否掉）：①引擎进网关＝违决策 38＋给「无智能」进程加路由职责；
  ②续用 bash＋外部小工具＝管线破碎、不可单测。

### 1.2 引擎＝水位游标＋行重放；Observe 流只当门铃

路由匹配的真源选 **`ticket_event` 表行**，不选流载荷：

- 行全序（`id` AUTOINCREMENT）、持久、含 provenance——水位线天然＝「已处理最大 id」；
- 断线补报与活径**同一段码**：启动/重连/每个 poke 都调 `EventsAfter(wm)` 再处理新行，
  漏报在结构上不可能（漏了就是 wm 没推进，下次 poke 或下次启动必然捞回）；
- 不需要给 ObsEvent 加序号、不需要处理「emit 与落行的先后对齐」。
  代价是每次 poke 多一次本地 RPC 往返——本机 socket 查一张小表，忽略不计。

**配套不变式**：可路由事件必须是 `ticket_event` 行；emit 只负责叫醒，内容不被路由消费。
两处顺手对齐（emit 与 AppendEvent 颠倒处：`budget_frozen/budget_stop/shell_*/spawn_blocked/
inject_failed/budget_reset_failed/shells_exhausted`）——门铃先于落行的窗口会被下一 poke
或重启补回，对齐只是让它严格因果，非正确性必需。

### 1.3 adjunct 席——为裁决/诊断类「不占相位的辅助实例」立型

`stall_suspect→派 CTO 裁决席` 直接撞现状：`DispatchSeat` 对 `施工中` 票返回「不可派」
（相位步行只认 已立→已派）。且裁决席不应：把票推离施工中（票不是它的）、
用自己的进度帧喂票闹钟（遮蔽施工席的卡死检测）、Deliver 走 施工中→待审。

故立 **adjunct 席**：绑定票的辅助实例，命不属相位——

- `DispatchReq.adjunct=true`＋必给 `prompt_file`（事件触发的定制提示，不走注入机——
  注入机吃票面八栏，裁决席吃的是**触发事件上下文**，两者输入不同源）；
- `seat_run.adjunct` 列（schema 增列＋Open 时幂等 ALTER）；
- claim→仅记 `adjunct_claim` 行**不转相位**，但**重挂票闹钟**（裁决席到来后若它自己也无声息，
  闹钟再响→下一个裁决席——自升级环闭合，预算硬顶兜底）；
- progress/usage→照常落行并挂闹钟（语义对：票上有活性即非死）；**usage 只计 `used_total`**
  （票级硬顶，§5.5 钦定各席消耗同账）**不进 `used`**——adjunct 不是施工「尝试」，不占尝试帽，
  否则裁决席用量能把施工席误判过 100% 硬停；
- **派发侧**：adjunct spawn **跳过 `ResetAttemptUsage`**（它不清施工的尝试账）与 `warned` 复位；
- deliver/yield→仅记 `adjunct_deliver`/`adjunct_yield` 行，不转相位；Ack 照回；
- dead→仅发 `adjunct_dead`，不回队、不罚壳健康、不占 failSet；
- 重启边界：adjunct run **不被启动对账收养**（`ActiveRunForTicket` 只看 non-adjunct；
  裁决席流断→宽限到自退 `adjunct_dead`→卡死再响→新裁决席，自愈不欠账；
  若要收养得加「票上全部活 adjunct run」查询——不值，弃）；
- **去重闸**：同票同角色已有活 adjunct run→Dispatch 拒（防裁决席堆叠；死席让位）。

### 1.4 裁决回流＝`SeatMsg.rule` 帧，不是读产物再解释

裁决席（无头壳）唯一能说话的地方是席位流。候选：

- 壳在 stdout 最后一行打哨兵 `META_RULE:<action>:<理由>`；`meta seat` 扫描行命中哨兵→
  发 `SeatMsg.rule{action,note}`（哨兵是壳与外壳的约定，不进 adapter——与壳无关）；
- 网关 `handleRule` 机械校验：`run.adjunct && role=="CTO"`，否则拒。

**否掉**的替代：读裁决席产物文件再解释（两层异步＋文件约定脆弱）；复用 `Deliver.note`
承载裁决（语义混装）。`Rule` 本就是 §12 预留名（原挂 CEO 面）；放席位面是同一语义的不同入口——
席位已是验过 run_token、绑过票的说话方，就近放最省面。

**动作两枚**（C 唤起钦定）：
- `kill_requeue`：取该票最新活 **non-adjunct** run（`ActiveRunForTicket` 语义改 `adjunct=0`——
  它本就用于「杀谁/收养谁」，排除 adjunct 处处正确）→其壳键进本票 failSet（换壳，§5.2）→
  `killByGW`（不罚健康）→SIGKILL 进程组→既有 onRunDead 径自动 回队+重派下一壳；
  无活施工 run→幂等（相位仍 `施工中` 则补一条 requeue）。
- `defer`：`defer_count<K`（缺省 2，§5.2 A5）→`defer_count+1`、闹钟重挂全额
  `ProgressTimeout`，记 `ruling` 行；`defer_count>=K`→**不杀不挂**，转记 `defer_limit`
  事件行（＝§5.2「报 CEO」的机械落点，路由表接通知）——裁决席照常退场，闭环收敛不空转。

`ruling` 事件行（裁决已执+动作+理由）入表可配通知——业主能见到「卡死已裁：换壳重起」。

### 1.5 配置必载、出码外（D-9 的诚实义）

`meta serve --config <textproto>`：缺省路径＝`<可执行文件>/../config/gateway.textproto`
（生产布局 `/opt/meta/config/`），**文件缺/坏→serve 拒起**（fail loud——登记表在码里就不叫配置化）。
壳登记表种子从 `defaultRegistry()` 码内字面量挪进配置行——沿用 `shellsFor` 懒落种径
（角色行空才落，DB 行是活态：健康迁移仍走 `SetShellHealth`）；预算缺省值同理。

## 2. 路由表 schema（D-26 核心件）

proto 增（`proto/meta/v1/meta.proto`，textproto 解析走 `prototext`——R3 允许形）：

```proto
message RouteTable { repeated Route routes = 1; }
message Route {
  string kind = 1;                 // 匹配 ticket_event.kind（精确等值；表外事件不动作——铁律②）
  repeated Action actions = 2;
  string note = 3;
  string note_contains = 4;        // 可选：行 note 子串匹配（空＝只按 kind；§15.6 spawn_needed 分角色用）
}
message Action {
  oneof body {
    NotifyAction notify = 1;       // 调通知脚本，纯中文模板
    DispatchAction dispatch = 2;   // 调 AdminGateway.Dispatch——它不直接生孩子（铁律①③）
  }
}
message NotifyAction { string template = 1; }        // 占位符 {{ticket_id}} {{kind}} {{note}}
message DispatchAction {
  string role = 1;
  string prompt_template = 2;      // 模板文件（相对配置根）；渲染→临时文件→prompt_file
  string work_dir = 3;
  string prefer_shell = 4;
  bool adjunct = 5;
}
```

**预留 CEO 面**（阶段 3）：`budget_frozen`/`reject_limit` 行今只挂 notify；
阶段 3 在这些行加 `dispatch{role:"CEO", adjunct}` 即可——动作类型不用增，CEO 无头席
本就是一个 role=CEO 的 adjunct 实例（届时 CEO 行登记按 §7「业主写死」人工落种）。

**钦定件**：表存仓 `config/caster.textproto`，改表走票（部署同步到 `/opt/meta/config/`）。

## 3. 匹配引擎接法（`meta caster` 主循环）

```
meta caster --socket <sock> --routes <f> --state-dir <d> --run-dir <rundir>
            --notify-cmd <sh> [--once]

connect AdminGateway → 起 Observe 流（先订阅再对账，缝闭两侧）
→ resync：循环 EventsAfter{since_id: wm, limit:500} 至短页，
  逐行 process(row)（路由表匹配→执行动作）→ 每行处理完原子写 wm=row.id
→ 活径：每收一条 ObsEvent → resync（同一段码）
→ 流断 → 退避重连（1s→60s cap，重试不设上限＝流订户续订，
   传输层重试不受 R2 限——边界条款明示合法）
   → 重连成功即 resync（断线补报=同码径，见 §4）
--once：只 connect+resync 一次即退（测试与手动追平径）
```

- **process(row)**：`route.kind==row.kind` 精确匹配；notify→渲染模板→`exec notify-cmd <文本>`
  （feishu-notify.sh 现成适配层，JSON 止于它）；dispatch→渲染 `prompt_template`
  （占位符 `{{ticket_id}} {{kind}} {{note}} {{run_dir}} {{gateway_sock}}`）写
  `<state-dir>/prompt-<ticket>-<rowid>.md` → `Dispatch{adjunct 行内值}`。
- 动作执行串行、有界（notify/dispatch 单次调用，错误→记一行日志行入 stderr/journal——
  播报员自身哑掉比刷错通知更不可见：notify 失败仅记，dispatch 失败重发一次（有界重试 1 次））。

## 4. 断线补报序（D-25）

- **水位线文件** `<state-dir>/watermark`（0600）：内容＝已处理最大 `ticket_event.id`；
  写＝tmp+rename 原子换。**文件缺失≠0**——初装「快进模式」：resync 照跑但只推 wm
  不动作（不吃历史剩饭，防旧 stall/claim 行补发成误派误报）；此后正常处理。
  需要追补历史由运维显式播种 wm 或 `--replay-history` 旗。
- **启动对账**＝§3 的 resync（启动事件驱动，零定时）：播报员 systemd 单元每次拉起
  （启动/崩溃复活）都先捞 `id>wm` 全量行回放——漏报的关键节点照原模板补发/补派。
- **语义**：at-least-once——处理完才推 wm，崩在动作后写盘前→该行重放一次。
  notify 重发一条＝无害；dispatch 重放被 §1.3 去重闸挡（活 adjunct 拒派）。
- 补报不加「补报」前缀——业主视角「该来的通知来了」即正确；补发历史全在
  `ticket_event`（provenance 可查）。

## 5. stall→裁决 全链时序（清 D-16）

1. 施工席闹钟响→`onStall`：`stall_suspect` 行 note 带 `run=<施工runid>`（取
   `ActiveRunForTicket(adjunct=0)`）→emit。
2. caster poke→resync→命中行→通知＋dispatch：渲染 `stall-ruling.md`
   （含 ticket/run/log 路径线索）→`Dispatch(adjunct, role=CTO)`。
3. 网关：adjunct 派发→`EnsureBudgetDefaults(CTO 帽)`→spawn 裁决席→claim→重挂闹钟。
4. 裁决席读 `{{run_dir}}/logs/<runid>.log` 尾＋必要时 `meta runs/events --socket {{gateway_sock}}`
   →stdout 打 `META_RULE:kill_requeue:空转确认` 或 `META_RULE:defer:真在干活`。
5. `handleRule`：kill→施工壳进 failSet→杀→回队→自动重派下一壳（换壳完成）；
   defer→帽内延期/帽尽→`defer_limit`→通知。
6. 裁决席退场→`adjunct_dead`；全链闭环于事件，零定时。

`stall-ruling.md` 模板要点（钦定件，仓 `config/caster/`）：身份＝CTO-C 唤起；
输入＝该票卡死施工席 run（`meta runs --socket {{gateway_sock}} --ticket {{ticket_id}}`
取非 adjunct 行）及其日志尾 `{{run_dir}}/logs/<runid>.log`；
裁决两选一并**最后单独一行**打哨兵；判据＝重复/空转/等许可→杀+回队换壳，
确在推进→延期（帽尽网关自动转 `defer_limit`，无需你量）。

## 6. 三驳（reject_limit）

- 网关加 `transition()` 包装（全 Transition 调用点收口）：迁移成功后发 `phase:<edge>` 门铃
  （补 `dispatch` 边一直缺的 poke）；`kind==EdgeReject` 时查 `reject_count`，达 3→
  `reject_limit` 事件行+emit。
- 现网无驳回写径（审计席未上机）——包装先立，审计判决径落地时事件自生；
  单测直接驱迁移验证 emit。非死码：它是对「过渡件」的预埋闸，不是摆设。

## 7. 配置文件形制（D-9）与缺省值（D-27 毛口径）

`GatewayConfig`（textproto，`config/gateway.textproto` 入仓）：

```proto
message GatewayConfig {
  google.protobuf.Duration progress_timeout = 1;  // 缺省 30m
  google.protobuf.Duration auth_timeout = 2;      // 5s
  google.protobuf.Duration adopt_dial_timeout = 3;// 2s
  google.protobuf.Duration stagger = 4;           // 10s
  google.protobuf.Duration quick_exit = 5;        // 20s
  int32 max_per_shell = 6;                        // 0=不限
  int64 default_attempt_cap = 7;                  // 角色行未配时的尝试内帽（毛值 token）
  int64 ticket_hard_cap = 8;                      // 票级累计硬顶缺省（毛值）
  repeated RoleBudget role_budget = 9;
  repeated ShellRow shell = 10;
}
```

## 13. 红线/禁区自查

- R2：引擎无定时器——wake＝Observe 流/进程启动；流断续订退避＝传输层重试
  （边界条款明示合法）；裁决重挂全走 `clock.Alarm` 一次性闹钟。
  网关仍零 Ticker（selfcheck 覆盖）。
- R3：表/配置皆 textproto；模板渲染产物是席位提示文本非接口；feishu JSON 仍止于
  `feishu-notify.sh` 适配层。
- R5：票状态只在 DB；水位线是播报员私有游标不是票状态副本。
- 「网关无智能」：路由匹配在 caster 内；网关只新增机械闸（adjunct 旗、rule 校验、
  计数帽比对）——计数/键比对皆机械判合法。
- 「播报员不直接 spawn」：dispatch 全经 `AdminGateway.Dispatch`——先连后领/run_token/
  预算/壳路由一口不破。
- 禁令#1 边界：重连退避、notify/dispatch 有界重试＝有界重试链；`--once` 无周期。
- 禁令#7：网关无「该不该」判断——kill/defer 裁决权在裁决席（智能体），网关只执机械闸；
  审计派发径同判：verdict 是席位给的 token，网关只做枚举→边的查表映射；判决对错归审计。
- R5/唯一写者：`RetroVerdict` 是 admin RPC（经网关过 transition() 包装），不是 CLI 直改
  DB——回翻两行与普通迁移同构落 ticket_event，事件即调用本身。
- 「无连接即无相位」边界唯一破例：`RetroVerdict` 的 audit_start 不凭连接凭 admin 令——
  补录性质已在 actor/note 显式留痕，且第二跳当场把票推离 审计中，不留「假审计中」挂席。

## 14. 未解项/风险

- **adjunct 席预算并入同一票硬顶**：裁决烧票的钱（§5.5 钦定如此），裁决循环最坏
  烧到 `budget_frozen`——止血正确但会把病票连人带闸一起冻住，靠 `defer_limit`/
  `budget_frozen` 双通知兜。若想给裁决席独立预算池，属新条款，须业主裁。
- **adjunct 模型是我新立的型**（票未动相位、席不占相位）——它是本设计最大的新增概念面；
  若审计/后续裁决认为「裁决席也应走相位模型」，整个 stall 闭环要重拆（备选：裁决席独立
  「裁决票」关联父票——更重，本设计未取）。
- 帽值毛口径基于单一数据点（0003 施工 20.18M）——40M/120M 是「实测×余量」的起手值，
  不是统计结论；跑几票后应按 ATIF 毛值分布回校。
- `reject_limit` 的 emit 先于审计判决径存在——包装预埋，单测驱动可达；§15 的判决写径
  （handleDeliver 审计支）落地时记得它就是那个写径，别再开第二条。
- 表匹配今按 kind 等值＋`note_contains` 子串（§15.6 为 spawn_needed 分角色加的惟一第二维）；
  更一般的 role 条件路由仍不泛化——新需求先加行，凑齐三例再谈 match 字段抽象。
- `note_contains` 是**子串脆配**：`spawn_needed` 行 note「对账补发： <role>」文案若改，表行
  须同步改——把「对账补发： <role>」视作半结构约定写进 reconcile 注释防漂。
- 审计席缺 B2 机器记录径（命令代跑是阶段 2 前置另一件，未立）：现阶段审计席自跑验证或读
  施工机器记录文件，与角色卡「读代跑记录不亲跑」的钦定终态有差——记为债（待代跑票收口），
  不阻塞本票派发径成立。
- `RetroVerdict` 只补相位链账，不补判决档本体——ref 指向的档必须在仓内已存（0003 判决档
  在 `docs/实现/票-0003-判决/`；0004 凭决策 40 验收记）；它同时是**唯一的 audit_start
  无连接破例**，破例理由与留痕形制见 §15.4。
- `deliver` 路由对一切 deliver 派审计——含设计票（0004 自身交付即起审计审设计），语义
  一致不区分票类；若日后有「免审交付」类须另立 kind 或票面旗，本表不预留。

## 15. 审计派发径（补章·决策 40）

> 决策 40 补范围：审计不再只靠手工径实例——「待审」票可派 `role=审计`、审计判决机械回流
> 相位、滞留历史票一次性回翻。审计席是**相位步行席**（非 adjunct）：它走票的相位，
> usage 进票级账（尝试内 used＋票级 used_total 双计——它是真尝试，吃审计帽）。
> 边表 `audit_start`/`audit_pass`/`reject`/`audit_dead` 早已钦定在册——本章是「接上调用」，
> 零新边。

### 15.1 派发闸：`DispatchSeat` 增「审计支」

- `role=="审计"`：相位闸＝**必须 待审**（已派/施工中/审计中一律拒——审错相位就是审错票）；
  **不走** `已立→设计中→已派` 步行——审计席的相位推进全部让位给 claim
  （与「无连接即无施工中」同构：无连接即无审计中，Dispatch 不代写相位）。
- 非审计 role 照旧步行到 已派；两条支路在「冻票拒派」与 spawn 队列上合流。
- **同角色活席去重**：`ActiveRunForTicket`（§1.3 已改 adjunct=0 语义）查到同 role 活 run
  →拒「该角色已有活席」。顺手焊死潜伏洞：原实现下 `已派` 票重派可双席并存（第二席 claim
  撞幂等重领被放行）——此后同角色活席在，重派即拒（死席让位照 `dead=0` 判）。
- **`g.specs` 键改 (ticket,role)**：审计派发不覆写施工派发参数——驳回重派施工时原 spec
  （含 `prefer_shell`）仍在内存，同壳语义自动保；spawn_blocked 注记带 role 可辨。

### 15.2 claim→audit_start；判决经 `Deliver.verdict` 回流

- `handleClaim` 按 `st.run.Role` 选边：审计→`Transition(→审计中, EdgeAuditStart)`，幂等相位
  ＝审计中（收养重领放行）；其余照旧 `EdgeClaim`→施工中。迁移经 `transition()` 包装，
  `phase:audit_start` 门铃照出——路由表 `audit_start`→通知（补决策 34「审计拉起没报」缺口）。
- proto `Deliver` 加 `verdict`：**审计席必填** `pass|reject`，其余角色必须空——非审计席带
  verdict→`InvalidArgument`（防语义混装，与 §1.4 否掉「Deliver.note 载裁决」同源纪律）。
- 审计席判决出口＝壳 stdout 哨兵 `META_VERDICT:pass|reject:<判决档ref>`（最后单独一行，
  与 §1.4 `META_RULE` 同约定、席位外壳**同一扫描点**）→ `meta seat` 填进
  `Deliver.verdict`＋`ref`。判决档本体是席位产物文件，网关只搬 verdict token。
- `handleDeliver` 审计支：`pass`→`EdgeAuditPass`→待部署；`reject`→`EdgeReject`→已派
  （`reject_count` 由 `Transition` 既有行自动 +1，达 3 由 §6 包装发 `reject_limit`）；
  verdict 空/非法→`InvalidArgument` 不落相位不回 Ack——席位退、票仍审计中，席死后走
  §15.3 audit_dead 自纠正径（**判不出判决的审计席＝死席，重起审计**）。
- 「驳回回施工中」（决策 40 语）＝机械净效果：钦定边表 `reject` 落点是**已派**（同壳重做；
  无连接即无施工中，不可直写施工中）→自动重派施工→claim 回施工中。
- 驳回重派施工双径（同 §5 双覆盖风）：①网关内 `enqueueSpawn(tid,"施工")`——spec 仍在
  （键含 role，§15.1）原 prefer 保；②路由表 `reject`→dispatch 施工——重启/参数失后由
  注入机重组（判决史含 reject 行，自动拼进新施工席前缀——「驳回理由累积，重做者必读」
  自此机械兑现）。两径在去重闸前幂等相会：先到者立席，后到者撞相位/活席闸被拒（日志留痕）。
- **同壳重做落点**：施工重派若走注入径（无 prefer），网关在 `reject_count>0` 时机械补
  prefer＝票上最近 non-adjunct 施工 run 的壳名（§7 ④同壳＝模型一致性偏好；failSet 排除权
  仍高——壳已死不在可选集则落下一行，不算破例）。
- 审计席闹钟照常挂：claim/progress/usage 全重置——**stall 机械对审计席零新码生效**：
  审计席卡死→stall_suspect→路由表派 CTO 裁决席（adjunct）→kill_requeue 杀的「最近
  non-adjunct run」恰是审计席→audit_dead→待审→重派审计，环自闭。

### 15.3 审计席死亡：audit_dead→待审，不计驳回

- `onRunDead` 增 `PhaseAuditing` 支：`Transition(→待审, EdgeAuditDead)`（钦定补边
  §6.2「审计席死→待审重起，**不计驳回**」）；`reportShell`/failSet 按①②分级照旧
  （审计席死是壳失效不是判决——①级不罚健康，与施工席死同一落账径）→
  内部 `enqueueSpawn(tid,"审计")` 重派（spec 在则秒接；失则路由 `audit_dead`→dispatch
  审计经注入机补位）。
- **启动对账零改动**：§5.3 钦定表早有「审计中→收养/回待审」「待审→补发 spawn」两行——
  本票把 `spawn_needed` 的消费者（路由表 `note_contains` 行，§15.6）接上即闭环。

### 15.4 相位回翻件：`RetroVerdict`（一次性机械补录）

- 用途：派发径立起前已交付、且**判决已在径外作出**的历史票——0003（手工正审通过已并
  `2d61f58`，判决档在仓）、0004（决策 40 票面验收通过）。DB 相位停 待审 与事实脱节，
  不回翻则永远是「交付未完」的假相。
- proto：`rpc RetroVerdict(RetroReq) returns (Ack)`；`RetroReq{ticket_id, verdict, ref}`——
  `ref` **必填**（判决档/决策号指证：无指证的回翻＝无 provenance 的相位篡改，闸挡）。
- 机械两跳（经 `transition()` 包装，事件行＋门铃照出——路由通知自动跟发）：
  `待审→审计中 (audit_start, actor="admin", note="回翻·人工判决补录")`
  →`审计中→待部署 (audit_pass)` 或 `→已派 (reject)`。相位闸＝**必须 待审**，否则拒——
  幂等（二次调用相位已走，拒绝留痕）；两跳皆走钦定边，边表零增改。
- CLI `meta retro --socket <sock> --ticket <id> --verdict pass|reject --ref <判决档>`：
  对 0003/0004 各跑一次即清账。`audit_pass` 落 **待部署**——与「判决通过等部署径」同格，
  不越「部署闸不存在」的现实；0003 支已并 master（事实部署先于部署闸），其后处置
  （作废/完成）归 CEO 令，本件不开 待部署→完成 捷径。
- 与「真补审」的分工：待审票要真起审计席＝`Dispatch(role=审计)` 即可（§15.1 闸天然
  接受）——`RetroVerdict` 只为判决已在径外作出的票补账，不是补审替代品，更不是
  绕审捷径（ref 必填＋事件留痕让它可被事后审计对账）。

### 15.5 与 adjunct 派发径的码位复用/区别

同一副骨架，两类语义——本表即实现地图（码位逐格对）：

| 码位 | adjunct（裁决席） | 审计席（相位步行席） |
|---|---|---|
| DispatchSeat | `adjunct=true` 旁支：闸＝票非终态非冻，相位不动 | `role=="审计"` 支：闸＝相位==待审 |
| claim | `adjunct_claim` 行不转相位，重挂闹钟 | `audit_start` 边→审计中，挂闹钟 |
| usage | `AddUsage(countAttempt=false)` 只计 used_total | `countAttempt=true` 双计（真尝试吃审计帽 15M） |
| spawn 前 | 跳 `ResetAttemptUsage`/`warned` 复位 | 照常清零复位（新尝试从零起账） |
| deliver | `adjunct_deliver` 行不转相位 | `Deliver.verdict`→audit_pass/reject 转相位 |
| yield | `adjunct_yield` 行 | 非法边（审计只许 verdict 或死） |
| dead | `adjunct_dead` 行：不回队/不罚壳/不占 failSet | `audit_dead` 边→待审＋failSet 分级＋重派审计 |
| spec 键 | (ticket,role) 共键（§15.1） | 同键 |
| 收养 | `ActiveRunForTicket` 排除→不收养 | 收养照旧（§5.3 表既有行） |
| 提示源 | 必给 prompt_file（事件上下文，不走注入机） | 空 prompt_file→注入机（角色卡＋八栏＋判决史） |

### 15.6 路由表新行（§2 钦定件已并入）

- `deliver`→通知＋dispatch 审计（prefer claude，prompt_template 空→注入机径）。
- `audit_start`/`audit_pass`→通知（补决策 34 缺口；audit_pass 暂不挂 dispatch{CTO-B}——
  部署闸未立，§8 预留语照写）。
- `reject`→通知＋dispatch 施工；`audit_dead`→dispatch 审计（§15.2/15.3 的外部位）。
- `spawn_needed`＋`note_contains:"审计"|"施工"`→对应派发——对账补发的消费端；
  新增 `Route.note_contains` 是唯一新匹配维度（kind 等值分不出角色——行无 role 列，
  角色在 note 文本）；表外 spawn_needed（CTO/部署）照铁律②不动作。
