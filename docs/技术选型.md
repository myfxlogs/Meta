# 技术选型

> 2026-11-01 议定。业主授权「最优解由设计席定」的四项。

## 1. 存储：SQLite 嵌入编排器

- 架构钦定「编排器是唯一写者」→ 嵌入式单写者库是自然配对
- 不需要 NOTIFY（事件在进程内）、不需要权限表、不需要跨机查询、不需要第二个容器
- proto 二进制存 BLOB，查询用列另立索引列；WAL 模式；备份=拷文件
- Postgres 只在跨机部署时才有理由——席位走本机 Unix socket 已钦定单机，故不选
- 行业印证：Sortie（无外部 DB 单二进制）、orch（SQLite）同选

## 2. 票面契约（八栏缺一不派）

换壳=重做，票必须让零上下文的壳冷启动即可干：

| 栏 | 内容 |
|---|---|
| 目标 | 一句话做成什么 |
| 为什么 | 来源需求/事故，让施工能答「我为何做这个」 |
| 范围内 | 允许触碰的目录/文件/面 |
| 范围外 | 禁线——不许碰的面（钱径/部署树/他票范围） |
| 设计引用 | CTO 设计文档在项目仓的路径+commit |
| 验收锚 | 机器可判的条目清单（审计席逐条打勾） |
| 验证命令 | 项目配方里的检查命令+本票专属测试 |
| 交付形制 | 支名规则、提交格式、交付=推支+gRPC Deliver |

另：预算（token 上限）、优先级、依赖票、判决史（驳回理由累积，重做者必读）。

借鉴：SwarmOS WorkUnit（Objective/Constraints/Acceptance/Plan Gate）。

## 3. CEO 形态

- **记忆在 meta 库**（备忘录+决策记录），不依赖壳自带记忆——壳可换，记忆不随壳走
- **交互实例**：业主在终端时的会话
- **无头实例（事件触发，不常驻）**：
  - 业主飞书来话而终端会话不在 → 起一实例应答
  - 需判断的系统事件（壳失效、三驳、全壳耗尽）→ 起一实例裁+转达业主
- **纯机械通知不动模型**：已部署/已换壳/壳恢复 → 编排器直推飞书
- 同一时刻最多一个 CEO 实例活（编排器持锁）——防两个 CEO 相互矛盾

## 4. 开源借鉴（引理念与零件，不引整机）

| 项目 | 吸收 | 弃因 |
|---|---|---|
| Paperclip（MIT，Node+React+嵌入 PG） | 预算 80% 警/100% 硬停；review 退回**原 owner**；公司/组织树为一等对象；适配器不规定壳的身份格式 | 心跳驱动=周期唤醒（红线 2）；Node/REST/JSON（红线 3/4） |
| Vibe Kanban（停更） | 执行器抽象：每壳一 executor + 命名配置变体（model/permission/plan） | 停更；JSON profiles |
| Sortie（Go） | 单二进制零外部依赖；`WORKFLOW.md` 式项目配方（tracker+agent+prompt 一件） | 轮询 tracker |
| Issue-Orchestrator | 「agent 出意图，编排器出权威」；只认实际产出的 commit 不信 agent 自述；有界返修 | 人并码；轮询 |
| SwarmOS | WorkUnit 票面 schema；带 fencing token 的 CAS 租约 | 无服务端 |
| orch（Rust） | SQLite；多项目单服务；重试间记忆（判决史）；复杂度路由到模型 | 内置 cron；JSON |

**共性结论**：全部轮询/心跳驱动、全部 JSON/REST——红线 2/3/4 整体排除。自建 Go 编排器，零件照单吸收。

**岔路记录**：若业主放松红线 2/3/4，Paperclip 可一日起公司。业主未松，自建。设计席判断：心跳驱动正是 v1 死法根源，不以成熟度换病灶。

## 4b. 派发模型对照：子代理 vs 异构无头壳

| | OpenClaw 子代理（sessions_spawn） | 本设计 |
|---|---|---|
| 派给谁 | 同进程 fork 的子会话——同模型/同工具/同 provider | 另一壳的独立进程 |
| 上下文 | 可 fork 继承，票可不完备 | 零继承，票必完备 |
| provider 挂 | 父子全挂 | 换壳续 |
| 审计独立 | 同模型自审 | 异壳审计 |

「一个脑子多只手」适合会话内并行；「多个脑子各一只手」才适合无人值守多日运行+失效替补。钦定后者。

**Grok Bot / Grok Ship** 对照：Firstmate 唯一对话口 / sqlite 为真源 / 推支后独立对抗审查——与本设计逐条重合，印证方向；弃因：托管电脑、单供应商（Cursor cloud）、人并码。

**OpenClaw Gateway** 借架构不借实现：一个常驻守护进程独占全部消息面，客户端/节点以角色接入 → **飞书通道归编排器所有，不归 CEO 壳**（壳可换，通道不断；飞书入站=事件→起 CEO 实例）。其 WS+JSON Schema+tick/heartbeat/cron 全踩红线，不引。

## 5. 编排器（综上）

- Go 单二进制，内嵌 SQLite，四面接口全 gRPC：
  - 席位面：本机 Unix socket 双向流（领票/进度/交付/许可问答）
  - CEO 面：事件流订阅 + 需求/裁决调用
  - 前端面：Connect 二进制，`SeatBoard` 流
  - 外部面：webhook 入站（JSON 止于适配层）
  - 消息面：飞书通道由编排器独占（借 OpenClaw Gateway 形），入站=事件
- 壳适配器：claude / devin / opencode 各一，统一接口（起/流读/用量/退码）
- 无智能：出事件、执闸、路由壳；裁决归智能体
