# 席位

> 业主钦定稿 2026-11-01。

## 四席

| 席 | 形态 | 职责 | 禁线 | 壳/模型 |
|---|---|---|---|---|
| **CEO** | **唯一交互席**，持久会话 | 与业主对话；接需求、出需求；接收系统一切需人知晓的告知并转达业主；项目业务裁决的转达口 | 不设计、不写码、不审计 | **业主指定**壳与模型 |
| **CTO** | 无头，事件触发的无状态实例 | 需求→设计文档→拆票→派发；审计通过→部署上线 | 不写实现码；不审计 | 系统自选：devin swe-2-max > claude(GLM) > opencode |
| **审计** | 无头，**独立实例**（不与 CTO 共实例） | 对照票面与设计验收施工交付；出判决（通过/驳回+理由） | 不改码；不设计 | 系统自选，**优先与该票的 CTO 实例异壳** |
| **施工** | 无头，事件触发实例 | 领票→实现→自测→提交→交付 | 不超票；不审自己；不部署；不碰部署树 | 系统自选：devin swe-2 medium/high > claude(GLM) > opencode |

- 一个实例一个角色，全程不换
- 席位记忆在 DB（票/判决/事件）与项目仓库文档里，不在进程里——实例死=无损失
- 并行度：每张票一个施工实例；每份需求一个 CTO 实例；每次验收一个审计实例。上限由预算配置

## 壳路由（席与壳解耦）

**登记表**：壳 × 模型 × 适用角色 × 优先序。CEO 行由业主写死，其余行系统按序选。

**失效分级**：

| 级 | 现象 | 处置 | 上报 CEO |
|---|---|---|---|
| ① | 进程起不来 / 秒退 | 换下一壳重起 | 是 |
| ② | API 报错、限流、配额尽、授权过期 | 标该壳不可用；换壳；该壳恢复由下一次需要它时试探（懒探，不定时探） | 是 |
| ③ | 无进度（见事件模型）/ 预算耗尽 | 报 CTO 裁：杀+回队换壳 或 延期 | 是（若换壳） |
| ④ | 交付被审计驳回 | **不换壳**，同壳重做 | 否（走正常票流） |

**换壳=票级重做**：壳间会话不互通，接手者从票面重新开始。因此**票面必须是完备契约**——施工所需一切在票里，不靠会话记忆。

**CEO 是唯一人机出口**：凡需要人工介入的（授权过期、全壳不可用、配额需充值、模型需调整），系统只有一个动作——告诉 CEO，CEO 告诉业主。系统不自行等待、不自行重试到死。

## 上报 CEO 的事件（清单，可增不可减）

- 任一壳被标不可用 / 恢复可用
- 任一票发生换壳
- 全部可用壳耗尽（交付停摆）
- 授权/配额/模型层面需人工处置
- 票完成部署（业主要的「有回应」）
- 审计驳回达 N 次（默认 3）——疑似票面本身有病，需人裁
- 生产健康探针红 → 回滚已执行

## 通道

- 业主 ↔ CEO：终端（电脑前）+ 飞书（移动端）
- 系统 → CEO：gRPC 流事件（CEO 会话订阅）
- 前端：只读席位板流（见事件模型）
