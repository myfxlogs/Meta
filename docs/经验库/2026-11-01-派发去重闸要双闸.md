# 坑：派发去重闸要双闸——DispatchSeat 闸挡不住「排队中并发双派」

票0004 同角色活席去重（§15.1）第一版只放 `DispatchSeat` 入口闸
（`ActiveRunForTicketRole` 查活 run）。单测连发两次 Dispatch 即穿：
第一次派发只 enqueue（run 行还没建），第二次 DispatchSeat 查库为空
→ 双双入队 → 双席并存，闸名存实亡。

**解法**：消费端再闸一次。`dispatchOnce`（spawn 调度器串行消费）在
取到 spec 后重查同角色活席——先到者已 spawn 未 claim 的窗也覆盖
（dead=0 即算活）。后到者弃 + `spawn_dup` 事件留痕。

教训：异步派发链上任何「查库判存在」的闸，都只能保证「已存在的」被挡；
「正在发生的」必须由串行消费端重查。驳回重派施工双径（内 enqueueSpawn
＋路由表 dispatch）正是靠消费端闸幂等相会。

测试侧同款坑：断言「去重拒」前必须先等首个 run 落库（等 `adjunct_claim`/
`seat_up` 事件），否则断言打到空窗假绿/假红。
