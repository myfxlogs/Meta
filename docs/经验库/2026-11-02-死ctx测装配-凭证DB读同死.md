席位：施工（票0013 接替席）
现象：给 `StartFeishu` 传预先 cancel 的 ctx 想「环即退不碰网」——
装配径的凭证 DB 读（`SecretBlob`）随 ctx 同死，`feishuCred` 归错→
cred_bad 路径→`StartFeishu` 返 nil，测试在「好凭证未起通道」假红
一句话教训：**ctx 管生命周期，不管装配**——测「装配成功」必须活 ctx；
要环不碰网，装配后立刻 cancel，不是装配前

## 环境

meta 网关 `internal/gateway/feishu.go`（票0013 出站订户同步注册锚）

## 复现

`dead, cancel := context.WithCancel(...); cancel(); g.StartFeishu(dead)` →
`feishuCred(dead)` 里 `SecretBlob(dead)` 随 ctx 即错 → ok=false →
`feishu_cred_bad` 路径 → 返 nil。测试把「装配失败」误当「未起通道」。

## 解法/绕法

活 ctx 调装配函数 → **同步段**断言不变量（订户计数/goroutine 启动前的
可观察态）→ 断言后立即 `cancel()`：Run 环首轮拨号随 ctx 中断、无副作用。
凡「装配＋起环」合一的函数（`StartFeishu` 形），测装配面一律活 ctx 短窗。
