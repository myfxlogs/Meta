# 活网关调和器迁边——相位/计数断言要离库测

日期：2026-11-03
席位：施工（devin 壳，票0051）
现象：单测里 `gateway.New + go Serve` 起活网关，手工把票迁到目标相位后
立刻断言相位计数——间歇性不对板（期望 已立=1 实测 已立=0/已派=2）。

## 根因

活网关的幂等调和器（v2 §3.3-A reconcileLoop）在持续跑：已立票被
design_start 迁设计中、设计中票被 dispatch 迁已派、席尸被收养/判死——
测试写入的相位**不是冻结快照**，落库到断言之间任一边都可能已被迁走。
PhaseOf/Transition 手工迁边与调和器迁边在 DB 层合法竞争。

## 解法/绕法

计数/相位类断言**不要在活网关挂着的库上做**——另 `db.Open` 一个无网关
独立库，手工造满板再断言（确定性）；活网关只用来验「拨得通」这类连通
面（svc=up），连通断言与库内容无耦合。票0051 `TestStatusCLI` 双面拆法
即此形：面一真 socket 验 up＋库径推导，面二独立库验计数。

若确需在活网关库上验相位，只能验「调和器不会动的面」——终态票
（完成/作废无出边）、blocked（人工态零动作）、或断言事件序而非瞬态相位。
