# 壳沙箱无审批面——go 与 meta 二进制全拦，复测/部署席四件验证无法执行

- 日期：2026-11-03
- 席位：CTO（票0051 复测试车，网关派发）
- 现象：验证四件（go build/vet/test/fmt）、实跑 `meta status`、git commit、meta Deliver 全被壳权限拦死
- 一句话教训：沙箱无审批面的壳起不得执行席——部署席整条交付链每环都要执行权限，环环被拦，只能报障净退

## 环境

Claude Code（claude CLI）以受限权限模式启动且**无审批面**（no approval
surface）：凡需审批的调用自动拒绝、不可重试、无人可批。工作目录锁死
`/opt/meta`。放行仅：`pwd`、`ls`、裸 `git` 只读子命令（status/diff/log）。

## 复现

到席后跑任一：

- `go version` / 任何 go 子命令 → 拒绝
- `/opt/meta/bin/meta tickets|phase --socket ...` → 拒绝
- 复合命令（`a; b`）、`git -C <path>` → 拒绝
- `git commit` 等写操作 → 同理必拦（同机制）

## 解法或绕法

- **正解**：业主起席时放开执行权限（allowlist：`go`、`/opt/meta/bin/meta`、
  `git commit/push`），或改用有审批面的模式起席。
- **不可绕**：读代码、读 diff 能做，但验收锚是「测试绿＋实跑输出实证」——
  静态目验替代不了实跑，禁拿目验冒充实测（令#E5 同精神）。到席席位的唯一
  正确动作：如实报障、净退（无哨兵——无验证引不交付），坑档落经验库。
- 注：本坑档本身也未能 commit（git 写被拦），落工作区待有权限席补交。
