# 经验：map 零值当「缺步判据」——缺键即算齐绿

> 令#E1 一坑一文。发现：T26 病4 完成态判（deployStepsDone）首版。

## 症状

四步配方完成判定写成 `last := map[string]int{step:exit}; for s in 四步 { if last[s]!=0 → false }`——
**缺键返回零值 0**，没跑过的步被当成「最近退码=0」即算齐绿。后果：deploy 票
只跑完 integrate 一步就被落 完成；17 个部署测试连环红（exec 闸拒「相位
完成 非 部署中」）。

## 一句话教训

**用 map 存「步骤→结果」做存在性判时，零值与缺键同形**——必须双判
`code, ok := m[k]; if !ok || code != want`。`m[k]!=v` 单判只挡「跑过且错」，
挡不住「根本没跑」。

## 规约

- Go map 值类型零值恰是「合法成功值」（0/false/""）时，存在性检查一律
  comma-ok 双判，写进代码 review 自检项。
- 同族坑：`count[k]++` 后 `count[k]>0` 判存在（这个反而对——零值恰好
  是「零次」语义）；坑只在「零值=成功」语义错位时炸。
