# 收错配席：杀进程让对账判死，别先手标 dead=1

日期：2026-11-02
席位：CEO（devin 上身）
现象：手工 `UPDATE seat_run SET dead=1` 后再对账，票被错派施工——D-51 角色分流整体失效
一句话教训：只杀进程，标死交给对账——先标死会让 ActiveRunForTicket 查无此行，死席角色血统丢源

## 环境
对账「施工中」回退依赖死席 run.Role 分流（CTO→已立/施工→已派）。ActiveRunForTicket/LatestRunForTicket 口径各异，均不看 dead=1 行里的活证据。

## 复现
req-f88 错配施工席在跑 → 手工 `UPDATE seat_run SET dead=1` → `meta reconcile` → ActiveRunForTicket 返回 nil → 通用回退「已派＋补施工」→ 又一个错配席（第三连错配实证）。

## 解法
`kill -9 -<pgid>`（spawn 走 Setpgid，杀负 pid 连坐子进程）→ 等对账自己判死回退。D-55 起 MarkDead 已连坐杀进程组，网关径无此坑；手工径永远只杀进程不标行。adjunct 席同坑：pid 死后 dead=0 会拿去重闸永挡新席。
