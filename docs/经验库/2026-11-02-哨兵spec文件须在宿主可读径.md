# 坑：META_ADMIN 哨兵的 spec 文件路径必须指向席位宿主文件系统实时可读径

**实证**：req-f88ce228927f 设计席（run 71569da3a34e8eba，2026-11-02）把全部
设计档+票面 commit 到设计支 `c/req-f88ce228927f-design`（未并 master），
随后哨兵行引用 `/opt/meta/docs/实现/票-003{1,2,3}-*.md`——主检工作树从未有过
这批文件（分支未并），外壳 `adminSentinel → os.ReadFile` 静默失败：
`create_ticket` 落 **spec=NULL** 的三张子票（0031/0032/0033），`fill_spec`
整帧丢弃——父票八栏回填同样落空。失败**无任何回执进事件流**（仅外壳 stderr
一行），票照常立、对账照常派。

## 后果链

- 子票 spec NULL → 注入机「缺一不派」inject_failed → 对账 §5.3「已立一律补
  CTO-A」把**施工票当需求票**派设计席（0031 错派施工后施工席 yield，
  0032/0033 错派 CTO-A）。
- 哨兵行在**壳退出时**才被外壳最后一泵处理（devin -p stdout 缓冲——seat 日志
  全程 0B 实证）——中程发的 META_ADMIN 帧实效时机不可控，读文件那一刻文件
  必须在。

## 打法

- `META_ADMIN:fill_spec|create_ticket` 的 .md 路径：**指向 sentinel 触发时
  席位宿主文件系统确定可读的绝对路径**（`$META_ART_DIR/` 内文件最稳——工件
  目录必然存在且不依赖分支并轨）；引用仓内路径前先确认文件已在 master
  工作树。
- 立票侧防御建议（已报 CEO 立债）：create_ticket 收到 Spec=nil 应拒立或落
  事件告警，而非静默建 NULL-spec 票。
- 施工票被错派 CTO-A 的处置先例（0032 席）：侧流 grpcurl Attach 发
  `SeatAdmin.fillSpec`（spec_md 直接走 proto bytes，不依赖文件径）+ `Yield`
  泊车，`meta msg` 先落诊断（次序：msg→fill→yield——后续事件不许盖过
  req_pending 成最新行）。
