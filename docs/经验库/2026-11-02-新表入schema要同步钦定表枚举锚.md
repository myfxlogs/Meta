现象：schema 加新表 feishu_card 后全量测试红一处——
TestAnchorH_MigrationSmoke（迁移烟测）内嵌「钦定表」枚举 map＋表数断言，
新表不在枚举即报「非钦定表/表数不等」
一句话教训：**钦定枚举型锚＝对应白名单的同步更新点**——加表/加字段/加事件
类时先把验收锚的枚举改进去再跑锚，锚红不等于做错，是清单未归位

## 环境

worktree 支 t/0014-live-card（基于 t/0013-feishu-chan 叠放），Go 1.2x，
modernc sqlite。

## 复现

`internal/db/schema.go` 增 `CREATE TABLE IF NOT EXISTS feishu_card` →
`go test ./internal/db` → `表数 11 ≠ 10`＋`非钦定表: feishu_card`。

## 解法或绕法

把新表加进锚的 want 枚举并注释出处票号（`feishu_card: true //
票0014 第十一表`），表数断言改成 `len(want)` 不自硬编码——下次加表只动
枚举一行。同类枚举锚全仓已有先例（票0010 加 cmd_run 时同款修法）。
