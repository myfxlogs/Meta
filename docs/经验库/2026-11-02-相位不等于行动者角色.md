# 「施工中」相位混三类行动者——角色源取 run 血统不取相位

日期：2026-11-02
席位：CEO（devin 上身）
现象：req-f88 四连错配、patrol 票被派施工——凡按相位推角色的路径全错
一句话教训：相位≠行动者；角色真源＝LatestRunForTicket（最近非 adjunct run 含死行）

## 环境
「施工中」混三类行动者：CTO 设计席（req-*/设计票）、施工席、巡检席（patrol-*）。roleForPhase 只认四相位，对混合相位一律回「施工」。

## 复现
设计席死→相位推「施工」补派；patrol 票回退→相位推「施工」补派；最早行口径→票合法换角色后钉回首任（设计完→驳回→返修又被送回设计）。三个方向各实证一次。

## 解法
角色源钦定 `LatestRunForTicket`（ORDER BY started_at DESC, adjunct=0）。配套不变量（D-55）：非 adjunct 席全票唯一闸（dispatch 拒异角色双席）；patrol-* 恒巡检；巡检角色只派 patrol-* 票；标死连坐杀进程组。
