# 经验：seat Attach 流断→收养重挂成功→帧泵仍空转（seat 侧断流无声族）

> 令#E1 一坑一文。发现：票 0016 CTO-A 设计席（run `acd0c6416bd56b79`，
> devin/swe-2-max）实机中招；绕行＝grpcurl Attach 同 token 直推帧落账。

## 症状链

1. Attach 流在 claim 后不明原因断开（DB `stream_closed=1`；seat 侧
   `pumpGateway` 见 EOF → `streamDead` → `waitAdopt` 挂 600s 收养钟）。
2. 断流期间 `enqueue` 静默吞帧：sendq 未满入队成功（老 sendPump 阻塞在
   `range sendq`，拉到帧后 Send 死流才报错退出——**该帧就此丢失**）；
   满则 `direct()` 返回 nil（streamDead 已立）→ 错误被调用方忽略。
3. 收养重挂（`Adopt` RPC → `attach()` → `MarkAttached` 落库为证）后
   **新流仍送不出帧**：队列里应排的 fill_spec/exec_probe/claim 无一落
   `ticket_event`、无 `admin_resp` 回执——帧泵（sendPump→stream.Send
   或 Recv 环）在新流上同样不立，且无任何日志（两条泵对错误全静默）。
4. 二次 Adopt → `attached_at` 再刷新 → 证实 waitAdopt 二期在等——
   流#2 在重挂后秒级再断。**断→收养→再断循环**，grace 600s 耗尽即
   `ExitOrphan` 席死回队（同缺陷会烧尝试数）。

## 绕行（实证有效）

同 token 开第二条 Attach 流直推语义帧——网关机械闸逐条适用，
无旁路（本例 fill_spec/Deliver 均落库，actor 仍记本 run）：

```bash
printf '%s\n' '{"auth":{"run_token":"<RUN_TOKEN>"}}' \
  '{"admin":{"fill_spec":{"ticket_id":"<T>","spec_md":"<B64>"}}}' \
  '{"deliver":{"ref":"<COMMIT>","note":"..."}}' \
| grpcurl -plaintext -proto proto/meta/v1/meta.proto -import-path proto \
  -d @ unix:///opt/meta/run/meta.sock meta.v1.SeatGateway/Attach
```

`run_token` 在 `seat_run` 表。注意：第二条并发 Attach 合法（网关无
单流位移闸）；帧丢失静默性来自 seat 的「拉走即丢」sendPump 语义。

## 疑似根因面（待修票认领）

- `waitAdopt`→`attach()` 成功后 `streamDead=false`、`go pumpGateway()`，
  但 sendPump 生命周期与流断代耦合：老泵退出时点与新帧入队时点有
  竞争窗（帧被老泵拉走送进死流＝黑洞）。
- `stream_closed` 闩锁语义：一次置位永不清，二次断流不可见（DB 面
  无法分辨「第 N 条流断」——对账/观测全盲）。
- 全程无日志：sendPump Send 错无 stderr、pumpGateway Recv 错无
  stderr——断代无声（本坑三小时才确诊，就因为零噪音）。
- 与 D-42 同族不同层：D-42 是「哨兵文面被包裹/合并」，本坑是
  「seat↔网关传输断代后无声不恢复」——判决/交付回流第二条失聪径。
