# 经验：裸立票不点火——created 事件无路由，已立滞留无人派（点火洞族）

> 令#E1 一坑一文。发现：票 0037/0038（2026-11-02，终端 CEO `meta ticket new`
> 径）；业主抓到「没有进入流程」。

## 症状链

1. `meta ticket new` 立票成功，事件流只有一行 `created →已立`，之后死寂。
2. caster 路由表无 `kind: "created"` 行——该事件是全表唯一无路由的事件
   （E13「看见即路由」在这里漏了）。
3. 对账（reconcile）只在网关启动时跑一次（§5.3 非周期）＋人工 RPC；立票
   发生在启动后 → 两条安全网都够不着。

## 根因

每条立票径本应自带点火载体：需求径（SubmitRequirement）自带 CEO 泵直接
唤 CTO；巡检径自领（adjunct_claim）。**裸立票（AdminGateway.CreateTicket）
没有载体**——设计默认「立票者负责点火」，终端径没接这一段。

## 边界（不是缺陷的部分）

- 立票后被「设计锁由票 XXX 持有」拒绝派发＝**正常排队**（项目内设计串行），
  锁释有补发消费端（spawn_needed: 锁释补发）——别把排队当滞留修。

## 规约

1. 终端立票后必须补一脚 `meta reconcile`（根修前的人工径）。
2. 根修＝票 0039：票事件去抖唤醒对账闹钟——任意相位变迁重置一次性闹钟，
   醒时跑既有 reconcile；一处修全局免疫（派发重试耗尽/锁释漏发同愈）。
   **勿走「caster 加 created 路由」**——会把 CTO 误派到 patrol-* 票上，
   对账消费端才有相位×行动者判别。
