## 2. 原则（v2 的五条，替代 v1 的 R1–R5 中的 R2，其余保留）

| # | 原则 | 替代/保留 |
|---|---|---|
| P1 | **全无人** = 正常径零人工 + 异常径安全停并通知。无人 ≠ 永不停 | 保留 R1，重新定义 |
| P2 | **控制面确定性**：网关里不许有任何 LLM 调用；一切处置查表 | 把 v1 禁区#7 从"禁判断"升级为"禁调模型" |
| P3 | **异常只有三种出口**：机械重试（有界、查表）／安全停＋通知／回滚。**没有第四种**。LLM 永远不被异常唤起 | 废 E18"看见即路由"中的"派无头席处置"一支 |
| P4 | **幂等调和替代事件补发**：允许一个周期性、幂等、无副作用放大的 `reconcile()`；禁止"事件→补发事件"链 | **废 R2，改为 R2′：禁周期性调模型，不禁周期性查本地表**（业主裁：R2 原本防的是计费炸弹，不是防零成本的本地纯函数）；R5 单真源不变 |
| P5 | **立票权只在人**：业主终端／飞书白名单／外部面经 Mandate 过闸。任何席位（含 CEO 化身、巡检）不得 `ticket new` | 新增 |

借 dsh 四件：Mandate 不可变授权书、只记录模式（影子期）、Eval 作无状态纯函数、"先落库后执行"。

### 3.3 新增

**A. 幂等调和器（替代一切补发）**

```
每 60s（或任意事件后立即）跑一次 reconcile()：
  for 每张非终态票:
    desired = f(phase, 失败表)        // 纯函数：该相位应有哪个角色的活席，或应停
    actual  = 活 run（SIGCHLD/EOF 已消的不算）
    if desired == actual: continue
    if desired == STOP: 票置 blocked（若尚未）→ 一条通知；continue
    if actual 缺 && 本票本相位尝试数 < 帽: spawn(desired)   // 唯一会起席位的地方
    else: 票置 blocked → 一条通知
```
- 幂等：同一状态跑 N 次结果一样；没有"补发事件"，所以不会放大。
- 一个时钟，一个入口，一个 spawn 点。`dispatcher()`/`spawnQ`/去抖/补发全部并入。
- 派发参数不再存内存：`spec` 由 `(票面, 角色, 项目配方)` 纯推导，重启零丢失（消灭 D-15 和 5008 条 spawn_blocked）。

**B. 失败表（确定性，配置文件，改表走票）**

| 事件 | 处置 | 上限 | 到限 |
|---|---|---|---|
| 席秒退 / 起不来 | 换下一壳 | 壳列表用尽 | blocked |
| 限流 429/5xx/连接错 | 退避重试同壳 | 3 次 | 换壳 |
| 配额尽 / 授权失效 | 标壳不可用，换壳 | — | 全壳不可用→blocked |
| 进度帧超时 30min | 杀，同票重派换壳 | 2 次 | blocked |
| 审计驳回 | 同壳重做 | 3 次 | blocked |
| 部署检查红 / 探针红 | 回滚 | 1 次 | blocked |
| 票预算到顶 | 冻 | — | blocked |
| 任何未知错误 | — | 0 | blocked |

`blocked` 是**人工态**：一条飞书通知（票号、最后一步、机器原因原文、三个可选动作：放行/重试/作废）。此后系统对该票零动作，直到人回一句话。业主"不盯"的保证来自：表上每一行都有上限，上限后一定停，停了一定只响一次。

**C. Mandate 授权书（替 provenance 字符串）**

票表加 `mandate` 列（proto BLOB）：`{来源种类(terminal|feishu|external), 来源身份, 范围(项目/允许路径), 强度(explicit|inferred), 策略版本, 签发时间}`。不可变；范围变大＝新票。所有 `transition` 到施工中/部署中前核 mandate 仍有效（策略版本未撤）。席位提示里的任何文字都不能改变它。

**D. 外部面影子期**

§6.3 自动票径保留五道闸，但新增第 0 道：**项目配方 `auto_ticket_mode: record_only | live`**，缺省 `record_only`——过闸事件只写一行"本会立票：<标题>"进 `ticket_event`，不建票不派席。业主看一周记录觉得对了再切 `live`。

**E. 无头 CEO 收敛成 Eval 纯函数**

保留无头 CEO 只用于**业务裁决**（外部需求歧义、动钱、范围外），触发源只剩 `feishu_inbound` 和 `requirement`。形态改为：输入＝需求原文 + 票面快照 + ceo_memory 最近 N 条；输出＝一个结构化 `Decision{accept|reject|ask, 定向, 理由}`；无 shell、无 `ticket new`、无 `dispatch`。决策入 ceo_memory 由网关代写，不由席位自述。

## 4. 相位机（简化版）

```
已立 →(reconcile 起 CTO)→ 设计中 →(CTO deliver)→ 已派 →(起施工)→ 施工中 →(deliver)→ 待审
  →(起审计)→ 审计中 →(pass)→ 待部署 →(起 CTO-B / cli-drive)→ 部署中 →(三锚绿)→ 完成
任一相位 ×失败表到限→ blocked（人工态）→ 人：放行(回原相位)/重试(回上一相位)/作废
```
去掉的边：回队自动重派（并入 reconcile 判定）、Yield 触发 CTO 裁决（Yield＝blocked）、设计中/审计中/部署中席死各自的回边（全部＝reconcile 看到 actual 缺则按表起或停）。相位从 9 个保留 9 个，边从 14 条减到 10 条。

## 5. meta 自身的升级径（去自指）

- meta 从 `project{}` 登记表中移除。meta 不是 meta 的客户。
- 升级 = `go test ./... && go build` 绿 → `meta upgrade --new <bin> --install <path> --prev <p>`（已有件）→ 人按一次回车。保留 systemd `OnFailure` 回退上一版。
- 网关重启丢失为零（§3.3-A 派发参数纯推导），所以升级代价只是几秒停摆。
- 允许一个例外：**meta 的票可以由 meta 的施工席写码并由审计席审**，但部署这一步永远是人。这保留了"自举"的大半价值，去掉了手术台上做手术。
